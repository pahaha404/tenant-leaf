# Pull Request와 통합 규칙

## PR 작성 전

- 빌드·테스트 또는 수동 확인을 수행했는가?
- 공통 API·상태값을 바꿨다면 관련 담당자에게 알렸는가?
- 실제 기기·실제 AI 호출을 확인하지 못했으면 명시했는가?
- `.env`, 원본 이미지, 모델 파일이 포함되지 않았는가?

## PR 설명 양식

```text
## 변경 내용
- 무엇을 만들거나 고쳤는지

## 계약 영향
- API / 데이터 형식 변경 없음 또는 변경 내용

## 확인 방법
- 실행한 빌드, 테스트, 수동 확인

## 미검증 또는 위험
- 예: Meta 실기기 미검증
```

## 병합 기준

- 다른 팀원 1명 이상이 내용을 확인한다.
- 공통 계약·안경·AI 데이터 변경은 해당 담당자가 확인한다.
- PR은 `develop`으로 병합한다.
- 데모 직전에만 `develop -> main` PR을 만든다.
