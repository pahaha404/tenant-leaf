# PM·통합 작업 순서

1. 매주 P0·P1·제외 범위를 루트 `Task.md`에 고정한다.
2. 화면 변경은 제품 문서와 디자인을 먼저 맞춘다.
3. API·AI·안경 연동의 계약 변경을 한곳에 기록하고 담당자에게 알린다.
4. PR이 `develop`에 병합될 때마다 Android·API·AI·안경 상태를 확인한다.
5. 실패 시나리오를 포함한 통합 QA를 수행한다.
6. 데모 직전에 `develop -> main` PR을 만들고 실제 흐름을 점검한다.

통합 담당자는 다른 역할의 코드를 대신 대규모 수정하지 않고, 변경을 담당자에게 이슈 또는 PR로 분리한다.
