# 세입세잎 백엔드 개발 순서

## 한눈에 보기

```text
기능 정리 → 기술 선택 → 개발 환경 → 기본 기능 → 임장 기능 → AI 연결 → 리포트 → 테스트·배포
```

앞 단계가 동작하는 것을 확인한 뒤 다음 단계로 넘어간다.

## 1. 만들 기능 정하기

- 첫 버전에 꼭 필요한 기능만 정한다.
- 사용자, 매물, 임장, 구역, 분석 사진, 관찰, AI 분석, 리포트를 기준으로 한다.
- 스마트 글래스·앱·백엔드·AI가 각각 맡을 일을 구분한다.

**완료 기준:** 팀원 모두가 첫 버전의 범위를 같은 내용으로 설명할 수 있다.

## 2. 기술과 구조 정하기

- 백엔드 언어, 데이터베이스, 이미지 저장소, 서버 배포 방식을 고른다.
- 처음에는 하나의 백엔드와 하나의 데이터베이스로 단순하게 시작한다.
- 이미지 파일은 데이터베이스가 아닌 별도 파일 저장소에 보관한다.

**완료 기준:** 선택한 기술과 선택 이유가 짧은 문서로 정리되어 있다.

## 3. 개발 환경 만들기

- 프로젝트 기본 구조를 만든다.
- 로컬에서 서버와 데이터베이스를 실행할 수 있게 한다.
- 코드 검사와 자동 테스트가 실행되는 CI를 설정한다.
- 서버 상태를 확인하는 헬스 체크를 만든다.

**완료 기준:** 새 팀원도 README만 보고 서버를 실행할 수 있다.

## 4. 사용자 기본 기능 만들기

- 로그인한 사용자를 확인한다.
- 사용자 정보와 이용약관·개인정보 동의 이력을 저장한다.
- 다른 사용자의 데이터에는 접근할 수 없게 한다.

**완료 기준:** 로그인한 사용자만 자신의 정보를 조회하고 수정할 수 있다.

## 5. 매물과 임장 기능 만들기

- 매물 정보를 등록하고 조회한다.
- 임장을 생성하고 시작·종료·취소할 수 있게 한다.
- 임장 상태를 저장하고 세션 전이·접근 권한을 검증한다.

**완료 기준:** 사진과 AI가 없어도 임장 시작부터 종료까지 진행할 수 있다.

## 6. 사진 업로드와 AI 연결하기

- 안경의 기본 고화질 영상이 휴대전화 갤러리로 가져와지는 흐름을 먼저 검증한다.
- Android가 촬영 완료 영상의 고정 3초 구간마다 JPEG 후보를 만들고 가장 선명한 한 장을 선택한다. 촬영 중 정지 사진 생성은 기본 녹화를 방해하지 않는다고 실기기에서 검증된 경우에만 선택적으로 사용한다.
- 원본 영상은 휴대전화에만 두고 촬영 종료 후 JPEG만 파일 저장소에 직접 올린다.
- 백엔드는 이미지 정보와 처리 상태만 관리한다.
- 먼저 가짜 AI로 전체 흐름을 완성한 뒤 실제 AI 모델을 연결한다.
- 곰팡이, 누수·물자국, 균열의 위치와 신뢰도 점수를 저장한다.
- 실패한 분석을 "하자 없음"으로 처리하지 않는다.

**완료 기준:** 사진 한 장을 올리면 AI 결과와 표시 위치를 앱에서 조회할 수 있다.

## 7. 리포트와 매물 비교 만들기

- 구역별 확인 필요 관찰, 근거 사진과 사용자 메모를 하나의 리포트로 만든다.
- AI가 확인한 내용과 사용자가 직접 입력한 내용을 구분한다.
- 여러 매물을 같은 기준으로 비교할 수 있게 한다.
- AI 결과가 확정적인 안전·계약 판단이 아니라는 점을 표시한다.

**완료 기준:** 한 번의 임장 결과를 저장하고 다른 매물과 비교할 수 있다.

## 8. 테스트하고 배포하기

- 다른 사용자의 데이터 접근, 잘못된 이미지, 중복 요청을 테스트한다.
- 여러 사용자가 촬영 종료 후 다량의 JPEG를 올리고 실패한 파일만 재시도하는 상황을 테스트한다.
- AI 지연·실패와 인터넷 끊김 상황을 테스트한다.
- 이미지 보관 기간, 사용자 탈퇴, 데이터 삭제를 검증한다.
- 스테이징에서 팀 내부 테스트 후 소수 사용자에게 먼저 공개한다.

**완료 기준:** 장애 대응, 데이터 복구, 배포 취소 방법까지 확인되었다.

## 가장 먼저 만들 데모

첫 데모는 아래 흐름만 완성한다.

1. 테스트 사용자 로그인
2. 매물과 임장 생성
3. 임장 시작
4. 이미지 한 장 업로드
5. 가짜 AI 결과 저장
6. 임장 종료
7. 간단한 리포트 조회

이 흐름이 안정적으로 동작한 뒤 실제 AI와 매물 비교 기능을 확장한다. 실시간 스트리밍 분석은 MVP 범위에 다시 추가하지 않는다.

## 공통 규칙

- 사용자 인증과 데이터 소유권 검사를 생략하지 않는다.
- 이미지 원본, 비밀번호, 토큰을 로그에 남기지 않는다.
- 기능마다 정상 상황과 실패 상황을 함께 테스트한다.
- 한 단계가 실행·테스트 가능한 상태가 된 뒤 다음 단계로 넘어간다.
