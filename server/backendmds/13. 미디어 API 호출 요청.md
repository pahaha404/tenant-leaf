# 역할

너는 Android·Kotlin·Jetpack Compose·OpenAPI 연동 경험이 풍부한 Android 개발자다.

# 작업 목적

종료된 임장의 원본 영상을 휴대전화 갤러리에서 감지하고, 영상에서 분석용 JPEG를 추출하여 Spring Boot 미디어 API와 MinIO에 업로드하는 기능을 구현한다.

# 기준 문서

다음 문서를 우선순위에 따라 확인한다.

1. `server/backendmds/도메인 규칙.md`

# 핵심 사용자 흐름

1. 사용자가 Android 앱에서 임장을 시작한다.
2. 앱은 임장 시작 시각을 기록한다.
3. 사용자는 Meta 안경으로 원본 영상을 촬영한다.
4. 원본 영상은 휴대전화 갤러리에만 저장한다.
5. 사용자가 임장을 종료하면 서버의 임장 상태를 `ENDED`로 변경한다.
6. 앱은 임장 시작 이후 갤러리에 생성된 영상 중 가장 최근 영상을 찾는다.
7. 조건에 맞는 영상이 정확히 하나이면 해당 영상을 임장 원본으로 자동 선택한다.
8. 영상이 없으면 가져오기 대기 상태와 재시도 버튼을 표시한다.
9. 후보 영상이 여러 개이거나 자동 접근이 불가능하면 최신 영상을 기본 후보로 보여주고 사용자가 확인하거나 Android Photo Picker로 직접 선택하게 한다.
10. 선택된 영상에서 계약에 맞는 JPEG를 추출한다.
11. 미디어 등록 API를 호출하고 발급받은 임시 업로드 URL로 JPEG를 MinIO에 업로드한다.
12. 업로드 성공 후 완료 API를 호출한다.
13. 업로드 진행률과 성공·실패·재시도 상태를 사용자에게 표시한다.

# 영상 및 개인정보 규칙

- 원본 영상은 휴대전화 갤러리에만 보관한다.
- 원본 영상 파일, 갤러리 URI, 로컬 파일 경로는 서버에 전송하지 않는다.
- 서버에는 분석용 JPEG와 계약에 정의된 메타데이터만 전송한다.
- 앱에 MinIO 계정, 비밀번호 또는 객체 저장소 비밀 키를 저장하지 않는다.
- 임시 업로드 URL은 로그에 출력하거나 영구 저장하지 않는다.
- 자동 영상 감지는 Android 권한 범위 안에서만 수행한다.
- 권한이 없거나 자동 감지가 불가능하면 Photo Picker를 대체 흐름으로 사용한다.

# JPEG 추출 규칙

- 촬영 후 영상에서 고정 3초 간격으로 JPEG를 생성한다.
- 각 구간의 앞·중간·뒤 후보를 비교하고 가장 선명한 사진 최대 1장을 선택한다.
- JPEG 품질은 90부터 시작한다.
- 2MiB를 초과하면 85, 80 순서로 낮추고, 그래도 초과하면 해상도를 단계적으로 축소한다.
- JPEG의 실제 영상 시점을 `sourceVideoOffsetMs`로 기록한다.
- 생성 방식은 `POST_RECORDING_EXTRACTION`으로 기록한다.
- 최초 구역을 확정할 수 없으면 계약에 정의된 `UNKNOWN`을 사용한다.
- 모든 후보가 흐려도 가장 나은 한 장을 남기되 화질 확인 필요 상태를 앱 내부에 표시한다.

# 미디어 API 호출 규칙

- `server/shared-types/openapi/openapi.yaml`의 미디어 API와 생성 타입을 사용한다.
- Android용 OpenAPI 생성 대상에 미디어 API와 필요한 모델을 추가한다.
- 생성된 `build/generated` 코드는 직접 수정하거나 Git에 커밋하지 않는다.
- 미디어 등록은 한 요청당 최대 20장이므로 20장을 초과하면 여러 묶음으로 나눈다.
- 각 JPEG에 앱에서 생성한 고정 `clientMediaId` UUID를 부여한다.
- 같은 사진을 재시도할 때 `clientMediaId`를 변경하지 않는다.
- 중복 요청 방지를 위해 같은 작업의 `Idempotency-Key`를 재시도에서도 유지한다.
- 등록 응답으로 받은 임시 URL에 JPEG를 `PUT` 방식으로 업로드한다.
- MinIO 업로드가 성공한 경우에만 업로드 완료 API를 호출한다.
- 임시 URL이 만료되면 업로드 재시도 API로 새 URL을 발급받는다.
- 자동 재시도는 최대 3회로 제한하고 이후에는 사용자 재시도 버튼을 제공한다.
- 미디어 등록과 업로드는 `ENDED` 상태의 임장에서만 진행한다.

# 화면 상태

화면에서 다음 상태를 구분한다.

- 원본 영상 가져오는 중
- 영상 확인 필요
- JPEG 추출 중
- 업로드 준비 중
- 업로드 중: 완료 장수/전체 장수와 진행률 표시
- 분석 대기
- 업로드 일부 실패
- 전체 실패
- 완료

앱이 종료되거나 화면이 이동해도 중복 업로드가 발생하지 않도록 작업 상태를 보존한다.

# 네트워크 오류 처리

다음 오류를 구분해서 사용자에게 안내한다.

- 서버에 연결할 수 없음
- 영상 접근 권한 없음
- 조건에 맞는 영상 없음
- JPEG 형식 또는 용량 오류
- 임시 업로드 URL 만료
- MinIO 업로드 실패
- 서버 완료 확인 실패
- 잘못된 임장 상태
- 재시도 횟수 초과

서버의 공통 `ErrorResponse`를 앱 오류 모델로 변환하고 내부 예외 메시지는 화면에 그대로 노출하지 않는다.

# 테스트

다음을 테스트한다.

- 임장 시간 이후의 최신 영상 선택 규칙
- 영상 없음·후보 여러 개·권한 없음 처리
- 3초 간격 및 `sourceVideoOffsetMs` 계산
- JPEG 크기 제한과 압축
- 20장 초과 시 요청 분할
- 동일 `clientMediaId`와 `Idempotency-Key` 재사용
- 임시 URL PUT 요청
- 업로드 완료 및 재시도 API 호출
- URL 만료와 네트워크 오류 처리
- 앱 재실행 시 중복 업로드 방지
- 원본 영상 URI가 서버 요청에 포함되지 않는지 검사

단위 테스트와 MockWebServer 테스트를 작성하고 Android 빌드·테스트를 실행한다.

# 실기기 검증

실제 Android 휴대전화에서 다음을 검증한다.

- Meta AI 앱을 거쳐 저장된 영상이 MediaStore에서 감지되는지
- 생성 시각과 임장 시간으로 올바른 최신 영상을 찾는지
- Android 버전별 영상 접근 권한 동작
- 자동 감지 실패 시 Photo Picker 대체 흐름
- 실제 서버 API 등록
- MinIO JPEG 객체 생성
- PostgreSQL `media` 행 생성 및 `UPLOADED` 상태 변경

Meta 영상 가져오기와 자동 감지를 확인하지 못했다면 완료 처리하지 말고 `실기기 미검증`으로 기록한다.

# 완료 조건

- 원본 영상은 서버에 업로드되지 않는다.
- 종료된 임장의 최신 영상 자동 감지 또는 사용자 선택이 가능하다.
- JPEG 추출, 미디어 등록, MinIO 업로드와 완료 처리가 연결된다.
- DBeaver의 `media` 행과 MinIO 객체가 동일한 `storageKey`로 확인된다.
- 실패와 재시도가 중복 데이터를 생성하지 않는다.
- 관련 Android 테스트와 빌드가 통과한다.
- 실제 검증 결과를 `android/android/Task.md`와 `공용 Task.md`에 기록한다.
