중요한 점은 문자열이 아니라 classId를 기준으로 변환하는 것입니다. 현재 실제 결과에는 water_damage, tile_crack처럼 계약과 철자가 다른 값도 있었으므로 Worker에서 고정된 classId-label 쌍으로 정규화해야 합니다.
모든 사용자 문구는 “균열”이 아니라 “균열로 추정되는 흔적 확인 필요”처럼 표현합니다.
2. 사용자 표시 신뢰도
현재 모델의 0.0325는 원시 후보 수집용 기준이지 사용자 표시 기준으로 사용하면 안 됩니다. 실제 테스트에서도 사진당 오탐 후보가 많이 생성됐습니다.
다음처럼 두 기준을 분리하는 것을 추천합니다.
- 원시 탐지 기준: 기존 0.0325, DB에 보존
- 관찰 생성 기준: 라벨별로 검증된 별도 임계값
- 임계값 미만: 관찰로 만들지 않지만 원시 탐지는 보존
관찰 임계값은 OpenAPI에 숫자로 고정하지 말고 모델 버전 설정으로 관리합니다.
modelVersion
classId
observationMinConfidence
configuredAt
AI 담당자와 실제 검증 사진을 이용해 0.1 / 0.2 / 0.3 / 0.5를 비교한 뒤, 최소한 사용자가 확인할 가치가 있는 정밀도가 나오는 값을 라벨별로 정해야 합니다. 임의로 전 라벨 0.5처럼 고정하는 것은 권장하지 않습니다.
3. 인접 사진의 반복 흔적 병합
무조건 합치면 서로 다른 흔적이 사라질 수 있으므로 조건부 병합을 추천합니다.
다음을 모두 만족할 때만 같은 관찰로 묶습니다.
- 같은 임장
- 같은 구역
- 같은 ObservationType
- sourceVideoOffsetMs 차이가 6초 이내
- crop 이미지 유사도가 기준 이상
병합된 관찰에는 근거 사진을 최대 3장까지만 연결하고, 신뢰도가 가장 높은 사진을 대표 근거로 둡니다.
MVP에서 이미지 유사도 비교까지 구현하기 어렵다면 자동 병합하지 않는 편이 안전합니다. 시간과 라벨만으로 서로 다른 균열을 합치면 안 됩니다.
4. AI 구역 분류
추천 규칙은 다음과 같습니다.
AI API 분류 성공 + 확실함
→ 해당 구역 저장

불확실함 / API 실패 / 지원하지 않는 응답
→ UNKNOWN
반드시 함께 저장할 필드:
- aiZone
- zoneConfidence
- zoneUncertain
- zoneModelVersion
- userCorrectedZone
- correctedAt
사용자가 구역을 수정해도 AI 원본 결과는 삭제하지 않습니다. 최종 화면과 리포트에는 사용자 수정값을 우선 적용합니다.
5. 모든 사진 등록 완료 알림
명시적인 미디어 집합 확정 API를 두는 것을 추천합니다.
POST /api/v1/inspections/{inspectionId}/media/finalize
Idempotency-Key: <UUID>
요청 예시:
{
  "expectedMediaCount": 21
}
서버 동작:
- 임장이 ENDED인지 확인
- 등록된 미디어 수와 expectedMediaCount 확인
- mediaFinalizedAt 기록
- 같은 멱등성 키 재호출은 같은 결과 반환
- 확정 후 새 미디어 등록은 409 Conflict
- 분석 성공 및 최종 실패 상태를 집계
이 API가 없으면 첫 번째 사진 분석이 끝났을 때 서버가 전체 분석이 끝났다고 잘못 판단할 수 있습니다.
6. 리포트 생성 시점
MVP에서는 자동 생성을 추천합니다.
Inspection = ENDED
+ mediaFinalizedAt 존재
+ 모든 미디어가 COMPLETED 또는 최종 FAILED
→ Report 자동 생성
결과 판정:
- 성공 미디어 1장 이상, 실패 없음 → COMPLETED
- 성공 미디어 1장 이상, 일부 실패 → PARTIAL_COMPLETED
- 성공 미디어 0장 → FAILED / NO_ANALYZABLE_MEDIA
- 분석 성공, 관찰 0건 → COMPLETED
관찰이 0건이어도 “하자 없음”이라고 표시하면 안 됩니다.
현재 촬영 근거에서 확인 필요 관찰이 생성되지 않았습니다.
리포트는 LLM 자유 생성보다 규칙 기반 문장으로 먼저 구현하는 것이 좋습니다. DISMISSED 관찰은 제외하고, 모든 문장은 근거 mediaId로 추적할 수 있어야 합니다.
최종 권장 흐름은 다음과 같습니다.
JPEG 업로드 완료
→ 미디어 집합 finalize
→ 하자 분석 + AI 구역 분류
→ 임계값 이상 탐지를 Observation으로 변환
→ 조건부 중복 병합
→ 모든 분석 종료
→ 리포트 자동 생성
→ Android가 실제 Observation·Report API 조회
