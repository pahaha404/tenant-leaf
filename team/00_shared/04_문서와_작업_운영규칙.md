# 문서와 작업 운영 규칙

## 폴더 역할

| 폴더 | 관리하는 것 | 수정 주체 |
| --- | --- | --- |
| `README.md` | 프로젝트가 무엇인지와 전체 구조 | 전원, PM 검토 |
| `DEVELOPMENT.md` | 설치·실행·개발 환경 | 구현 담당자 |
| `CONTRIBUTING.md` | 브랜치·PR·협업 절차 | 전원, PM 검토 |
| `AGENTS.md` | 사람과 AI 도구가 따라야 할 프로젝트 규칙 | 전원 합의 후 변경 |
| `docs/` | 제품 기준과 역사적 화면 문서 | 해당 역할 |
| `team/` | 공통 계약과 역할별 시작·작업 문서 | 전원과 각 담당자 |
| `공용 Task.md`, 역할별 `Task.md` | 일정, 통합·역할별 완료 기록 | PM과 각 담당자 |
| `server/backendmds/` | 서버·Android 연동 결정, 작업 범위와 완료 기준 | 작업 요청자와 담당자 |
| `server/technical/` | 서버 구조와 데이터 모델 기준 | 서버 담당자, 공통 계약 변경 시 공동 검토 |
| `design/` | pen.dev·이미지·디자인 참고 자료 | 디자인/Android 담당자 |

## README를 늘리지 않는 기준

- 루트 `README.md`는 한 페이지짜리 프로젝트 소개만 유지한다.
- `DEVELOPMENT.md`는 설치·실행 방법만 유지한다.
- `CONTRIBUTING.md`는 Git·PR 협업 규칙만 유지한다.
- `AGENTS.md`는 코드와 AI 작업의 절대 규칙만 유지한다.
- 폴더 README는 해당 폴더의 책임·진입점·실행 방법이 있을 때만 둔다. 내용이 한 줄이라도 경계를 설명하면 유지하고, 중복 설명은 링크로 대체한다.

## AGENTS.md 병합 규칙

- 루트 `AGENTS.md`는 모든 팀원·에이전트에게 적용되는 공통 규칙의 단일 기준이다.
- 특정 폴더에만 필요한 규칙은 그 폴더의 `AGENTS.md`에 추가한다. 하위 규칙은 루트 규칙을 반복하거나 완화하지 않고, 그 폴더에만 필요한 내용만 적는다.
- 서로 다른 브랜치에서 `AGENTS.md`를 수정해 충돌하면 한쪽 파일을 통째로 선택하지 않는다. 중복 규칙을 제거하고, 서로 양립 가능한 규칙은 모두 남긴다.
- 상충하는 규칙은 담당자·PM이 결정하기 전까지 병합하지 않는다. 예: Android 실행 명령과 API 실행 명령은 각각 하위 `AGENTS.md`로 분리한다.

## 작업 시작 순서

1. `team/<역할>/01_시작.md`를 읽는다.
2. `공용 Task.md`와 해당 역할 Task 문서를 확인한다.
3. 작업 대상과 가장 가까운 요청서·계약 문서를 읽는다.
4. 기능 브랜치에서 관련 폴더만 수정한다.
5. 구현과 실제 검증이 끝난 뒤 Task와 MDS 결과를 갱신한다.
