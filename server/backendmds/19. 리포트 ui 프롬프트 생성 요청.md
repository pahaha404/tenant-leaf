# 역할
너는 15년차 프론트엔드 개발자이면서 웹 디자이너야. 안드로이드 앱을 만드는 데 강점이 있어.

# 배경
현재 `세입세잎` 프로젝트에서 리포트 UI가 좀 부실한 것 같아.

# 요구사항
너가 생각했을 때 사용자 입장에서 리포트를 보게 된다면 ui를 어떻게 꾸밀 거야? 내가 그동안 냈었던 아이디어를 전부 가져오지 않아도 돼. 브랜드 컬러만 똑같이 차용하되, 하자 탐지 BBOX 사진을 사용자가 확인할 수 있으면 좋겠어. figma로 제작하려하니 영어 프롬프트를 만들되, ui의 결과물은 한국어로 나올 수 있게 해줘.

# 실행 결과

## Figma AI 프롬프트

아래 내용을 Figma AI의 프롬프트 입력란에 그대로 붙여 넣는다. 영어로 디자인을 지시하되, 화면에 표시되는 문구는 모두 한국어로 생성하도록 구성했다. 프롬프트는 Figma의 2,000자 제한 안에 들어간다.

```text
Design a polished Android mobile inspection report experience for a Korean rental-home app named “세입세잎”. Create 7 connected 360x800 screens: Report List, Generating, Completed, Empty, Partial, Error, and Full-screen Evidence Viewer. Keep the existing warm, trustworthy brand: off-white #FCFBF8 background, deep forest green #1E4933 text, primary green #2F6848, pale mint #EEF4EA cards, orange #F68B38 only for primary actions and warnings, thin #D9E1DA borders, rounded 16px cards, generous spacing, and clear Material-style hierarchy. Avoid gradients, glassmorphism, excessive shadows, and alarmist language.

All visible UI copy must be Korean. Use realistic labels such as “리포트”, “점검 리포트”, “작성 완료”, “분석 중”, “확인 필요 관찰 3건”, “참고 점수 85점”, and “매물 상세로 돌아가기”. Include the notice “AI 관찰은 하자 확정이 아니며 직접 확인이 필요해요.”

Completed: show date, property name and address, report status, provisional reference score, analyzed/failed photo counts, and sections grouped as “현관·공용”, “주방”, “창틀·환기”, “거실·방”, “화장실”, and “구역 확인 필요”. Explain the score as 100 minus 5 per visible observation; never present it as a safety score. Each observation card has an evidence thumbnail, Korean observation label, confidence, review badge, neutral explanation, and “근거 사진 보기”.

Evidence Viewer: show the original photo with pixel-accurate xyxy BBOX overlays while preserving aspect ratio. Use accessible box colors and chips such as “곰팡이 추정 76%”. Provide previous/next, zoom, close, and review controls. Highlight the selected detection but keep other detections visible. Never crop or stretch the image.

Generating shows real progress such as “사진 분석 14 / 21장”. Partial explains failed photos while preserving successful results. Empty says “확인 필요 관찰이 생성되지 않았어요”, never “하자 없음”. Error offers “다시 시도”. Place a sticky centered bottom button above system navigation: “매물 상세로 돌아가기”. Include loading, disabled, long-text, and accessibility-ready states with 48dp touch targets and high contrast.
```

## 화면 구성 원칙

- 리포트 목록에서 매물별 최신 상태와 확인 필요 관찰 수를 먼저 파악한다.
- 완료 리포트에서는 요약보다 실제 근거 사진과 관찰 항목의 연결을 우선한다.
- BBOX는 서버가 제공한 원본 이미지 좌표를 화면 비율에 맞춰 렌더링하고 원본 좌표를 수정하지 않는다.
- 낮은 신뢰도와 `other` 결과도 확정 표현을 피하고 사용자가 검토할 수 있게 한다.
- `EMPTY`, `PARTIAL`, `ERROR`, `GENERATING`을 별도 화면 상태로 설계해 빈 화면이나 무한 로딩처럼 보이지 않게 한다.
