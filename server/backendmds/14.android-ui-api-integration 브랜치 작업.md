현재 feature/android-ui-api-integration 브랜치에서 작업해줘.

목표:
최신 디자인 담당자의 Compose UI와 내비게이션을 그대로 유지하면서,
feature/api-media-contract에 보존된 실제 서버 연결 기능만 선별적으로 통합한다.

통합할 기능:
- OpenAPI 기반 네트워크 구성
- 매물 CRUD Repository·도메인·ViewModel
- 임장 생성·조회·종료·취소 Repository·도메인·ViewModel
- 영상 검색·선택
- 고정 3초 구간 JPEG 추출
- 2MiB 이하 JPEG 변환
- 미디어 등록·MinIO 업로드·완료·재시도 처리
- 공통 오류 처리와 관련 테스트

가져오지 않을 것:
- 기존 실험용 Compose 화면
- 기존 TenantLeafNavHost
- 기존 MainActivity
- 기존 온보딩 프로토타입
- 기존 테마와 화면 리소스
- 기존 실험용 내비게이션

통합 원칙:
- 현재 main/develop에 있는 최신 디자인 UI, 이미지, 테마와 화면 이동을 기준으로 한다.
- feature/api-media-contract를 통째로 merge, cherry-pick 또는 복사하지 않는다.
- 기존 디자인 화면의 임시 데이터와 버튼 동작만 실제 ViewModel과 API 호출로 교체한다.
- Gradle, Manifest, 버전 카탈로그는 디자인 빌드 설정을 보존하면서 필요한 네트워크·Hilt·OpenAPI 의존성만 합친다.
- 현재 서버는 DemoUserContext를 사용하므로 실제 토큰 로그인을 임의로 구현하지 않는다.
- 사용자 파일과 디자인 산출물을 삭제하지 않는다.
- 실제 사진·영상·API 키를 커밋하지 않는다.

작업 순서:
1. 현재 브랜치와 작업 상태 확인
2. Android 빌드 구조와 디자인 화면 흐름 분석
3. 네트워크 기반 구성 복원
4. 매물 기능 연결 및 검증
5. 임장 기능 연결 및 검증
6. 미디어 기능 연결 및 검증
7. 전체 빌드·단위 테스트·Lint 실행
8. 변경 파일, 검증 결과, 미검증 항목 보고

검증:
- :app:assembleDebug
- testDebugUnitTest
- lintDebug
- OpenAPI 코드 생성 및 문법 검사
- 가능하면 실제 기기 설치 확인

커밋과 푸시는 별도 요청 전까지 하지 않는다.
