# 백엔드 기본 구조 작업 요청서

## 작업 목적

기능 개발을 시작하기 전에 Kotlin Spring Boot API와 PostgreSQL을 누구나 같은 방법으로 실행하고 테스트할 수 있는 최소 기반을 만든다.

이번 작업은 사용자, 매물, 임장, 사진, AI 기능을 구현하는 작업이 아니다. 이후 기능을 안전하게 추가할 수 있는 실행 가능한 출발점을 만드는 작업이다.

## 담당 역할

- 주 담당: 백엔드
- 검토: 백엔드 담당자 1명 이상
- 연동 확인: Android 담당자는 API 주소와 헬스 체크 응답만 확인

## 수정 범위

- `server/api/`
- `server/infra/docker/`
- `.env.example`
- `.gitignore`
- `.github/`의 API 빌드·테스트 CI
- 루트 또는 API의 개발 실행 README
- 필요할 경우 `server/api/settings.gradle.kts`
- 구현 완료 후 `Tasks/backend/Task.md`와 `Tasks/README.md`

## 사용할 기술

- Kotlin
- JDK 21 LTS

- PostgreSQL

- 인증과 JWT 구현
- 사용자·매물·임장 CRUD
- 사진 또는 음성 업로드
- AI 작업자와 실제 AI 연결

- 운영용 모니터링

제외 항목은 기본 구조가 검증된 뒤 별도 요청서로 진행한다.

## 구현 요구사항

### 1. Spring Boot 프로젝트

- `server/api`를 독립적으로 빌드하고 실행할 수 있어야 한다.
- JDK 21을 기준으로 설정한다.
- 클래스와 파일 이름은 루트 `AGENTS.md`의 역할 중심 이름 규칙을 따른다.
- 패키지 이름과 애플리케이션 시작 클래스를 README에 기록한다.

### 2. PostgreSQL 로컬 환경

- Docker Compose로 PostgreSQL 하나만 실행한다.
- 데이터베이스 이름, 사용자 이름, 포트는 `.env.example`에서 예시를 제공한다.
- 실제 비밀번호가 들어간 `.env`는 Git에 포함하지 않는다.
- 데이터가 필요한 경우 이름이 명확한 Docker 볼륨을 사용한다.

### 3. 애플리케이션 설정

- DB 연결값을 소스 코드에 직접 넣지 않고 환경 변수로 받는다.
- 로컬 개발용 기본값에는 실제 비밀 정보를 사용하지 않는다.
- 로그에 DB 비밀번호, 토큰 또는 개인정보를 출력하지 않는다.

### 4. 데이터베이스 마이그레이션

- Flyway 마이그레이션 폴더를 만든다.
- 첫 마이그레이션은 연결과 실행 여부를 검증할 수 있는 최소 구조만 포함한다.
- 실제 도메인 테이블은 데이터 계약이 확정된 뒤 추가한다.
- 빈 데이터베이스에서도 마이그레이션이 자동으로 성공해야 한다.

### 5. 헬스 체크

- `/actuator/health`로 서버 상태를 확인할 수 있어야 한다.
- PostgreSQL이 연결된 상태와 연결되지 않은 상태를 구분해 확인할 수 있어야 한다.
- 헬스 체크 응답에 비밀번호나 내부 연결 문자열을 노출하지 않는다.

### 6. 테스트와 CI

- 애플리케이션이 시작되는 자동 테스트를 만든다.
- PostgreSQL 연결 또는 Flyway 실행 여부를 검증한다.
- CI에서 API 빌드와 테스트를 자동 실행한다.
- 실패한 테스트가 있는데 CI가 성공으로 처리되지 않게 한다.

### 7. 실행 문서

README에 아래 내용을 순서대로 작성한다.

1. 필요한 프로그램과 버전
2. 환경 변수 준비 방법
3. PostgreSQL 시작 방법
4. API 실행 방법
5. 헬스 체크 확인 방법
6. 테스트 실행 방법
7. PostgreSQL과 API 종료 방법
8. 자주 발생하는 오류와 확인 방법

문서에는 아직 구현하지 않은 명령을 미리 적지 않는다.

## 권장 프로젝트 구조

```text
server/api/
├─ build.gradle.kts
├─ src/
│  ├─ main/
│  │  ├─ kotlin/
│  │  └─ resources/
│  │     ├─ application.yml
│  │     └─ db/migration/
│  └─ test/kotlin/
└─ README.md

server/infra/docker/
├─ compose.yml
└─ README.md
```

실제 Gradle 멀티 모듈 구성에 따라 파일 위치가 달라질 수 있지만, API는 다른 서비스와 분리하여 실행할 수 있어야 한다.

## 검증 방법

1. `scripts/check-prerequisites.ps1`로 JDK 21과 Docker 설치 상태를 확인한다.
2. README의 명령만 사용해 PostgreSQL을 실행한다.
3. API를 실행하고 `/actuator/health`가 정상인지 확인한다.
4. 자동 테스트를 실행해 모두 통과하는지 확인한다.
5. 빈 데이터베이스로 다시 시작해 Flyway가 같은 구조를 생성하는지 확인한다.
6. PostgreSQL을 중지했을 때 헬스 체크가 연결 문제를 정상적으로 표시하는지 확인한다.
7. `git status`와 변경 내용을 확인해 비밀 정보와 불필요한 생성 파일이 없는지 점검한다.
8. 가능하면 작업하지 않은 팀원 한 명이 README만 보고 실행해 본다.
