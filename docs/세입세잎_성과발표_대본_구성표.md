## 1. 나에게는 너무 어려운 첫 자취!

### 화면에 넣을 내용

- 제목: `나에게는 너무 어려운 첫 자취!`
- 부제: `집 보러 갔는데… 뭘 확인해야 하지?`
- 프로젝트명: `세입세잎`
- 팀명은 확정된 이름으로 교체
- 밝은 원룸에서 어디부터 봐야 할지 고민하는 청년 이미지 한 장

### 발표 대본

안녕하세요. 저희는 첫 자취를 준비하는 사람을 위한 임장 기록 서비스, 세입세잎을 만들었습니다.

처음 집을 구하면 설레기도 하지만, 막상 집을 보러 가면 뭘 봐야 하는지부터 막막합니다. 창문도 봐야 하고, 화장실도 봐야 하고, 싱크대 아래도 봐야 하는데 시간은 짧습니다.

저희는 바로 이 순간에서 프로젝트를 시작했습니다.

### 다음 장으로 넘기는 말

그렇게 정신없이 집을 보고 나오면, 더 큰 문제가 생깁니다.

## 2. 분명 집은 보고 왔는데, 기억나는 게 없다

### 화면에 넣을 내용

- `창문은 잘 닫혔나?`
- `화장실에 곰팡이가 있었나?`
- `싱크대 아래도 봤어야 했는데…`
- `사진은 많은데 어디를 찍은 건지 모르겠다.`
- 스마트폰 갤러리에 비슷한 방 사진이 여러 장 쌓인 모습

설명 문단이나 문제 정의 표는 넣지 않는다.

### 발표 대본

저희도 집을 보고 나온 뒤에 비슷한 경험이 있었습니다.

분명 사진은 많이 찍었는데, 이 사진이 주방인지 화장실인지 헷갈립니다. 그때는 괜찮아 보였던 창문도 집에 돌아오면 잘 닫혔는지 기억이 나지 않습니다. 결국 다시 중개사에게 물어보거나, 중요한 부분을 확인하지 못한 채 계약을 고민하게 됩니다.

스마트폰으로 촬영하면 한 손은 계속 휴대폰을 들고 있어야 합니다. 집을 직접 만져 보고, 문을 열어 보고, 메모까지 남기려면 생각보다 정신이 없습니다.

### 다음 장으로 넘기는 말

그래서 저희는 촬영을 위해 손을 쓰지 않아도 된다면 어떨지 생각했습니다.

## 3. 안경을 쓰고, 평소처럼 집을 둘러보면 어떨까?

### 화면에 넣을 내용

- `AI 글래스로 현장을 촬영`
- `앱이 사진을 구역별로 정리`
- `다시 볼 부분과 근거 사진을 함께 확인`
- `마지막 판단은 사용자`
- 안경을 쓴 사용자가 방을 둘러보는 장면과 앱 화면 한 장

### 발표 대본

세입세잎에서는 사용자가 AI 글래스를 쓰고 평소처럼 방을 둘러봅니다.

안경은 사용자가 본 장면을 기록하고, 촬영이 끝나면 앱이 영상에서 분석할 사진을 골라냅니다. AI는 사진을 보고 다시 확인하면 좋을 부분을 찾아서, 근거가 된 사진과 함께 보여줍니다.

여기서 중요한 점은 AI가 이 집에 하자가 있다고 단정하지 않는다는 것입니다. AI는 확인이 필요한 장면을 정리하고, 실제로 문제가 있는지와 계약할지는 사용자가 판단합니다.

### 다음 장으로 넘기는 말

그런데 처음부터 지금처럼 단순한 구조였던 것은 아닙니다.

## 4. 처음에는 이것도, 저것도 다 하고 싶었다

### 화면에 넣을 내용

화면 중앙:

> 그런데 우리에게 주어진 시간은 한 달이었다.

주변에 흩어 놓을 초기 아이디어:

- 실시간 AI 분석
- 음성 메모와 STT
- 28개 현장 체크리스트
- 자동 점수
- 매물 순위 추천
- 영상 클라우드 저장
- 자동 리포트
- 매물 비교

### 발표 대본

처음 기획할 때는 욕심이 많았습니다.

촬영 중에 AI가 바로 알려주면 좋겠고, 말로 남긴 메모도 자동으로 정리하고 싶었습니다. 체크리스트를 모두 채우면 집에 점수를 매기고, 여러 매물 중 어디가 좋은지도 추천하고 싶었습니다.

하지만 이 기능을 전부 한 달 안에 만들면, 각각은 있어 보여도 처음부터 끝까지 제대로 동작하는 경험은 만들기 어렵다고 판단했습니다. 특히 실시간 영상 분석은 네트워크와 SDK 제약이 컸고, 원본 영상을 서버에 올리는 방식은 개인정보와 저장 비용 문제도 있었습니다.

그래서 무엇을 더 넣을지가 아니라, 무엇을 빼야 하는지를 먼저 정했습니다.

### 다음 장으로 넘기는 말

그 결과 네 가지 흐름만 남겼습니다.

## 5. 그래서 네 가지만 남겼다

### 화면에 넣을 내용

가운데에 크게 표시:

1. `매물 등록`
2. `글래스 촬영`
3. `JPEG 분석`
4. `근거 사진 확인`

주변에 작고 흐리게 표시:

- `실시간 분석 → 촬영 후 분석`
- `STT → 후순위`
- `자동 점수·추천 → 제외`
- `원본 영상 서버 저장 → 제외`
- `현장 체크리스트 입력 → 방문 전 가이드`

하단 문장:

> 많이 만드는 것보다, 처음부터 끝까지 이어지는 한 가지 경험을 만들기로 했다.

### 발표 대본

저희가 남긴 흐름은 네 가지입니다.

먼저 사용자가 방문할 매물을 등록합니다. 현장에서는 글래스로 영상을 촬영합니다. 촬영이 끝나면 Android 앱이 영상에서 JPEG 사진을 만들고, 서버와 AI는 그 사진만 분석합니다. 마지막으로 사용자는 다시 볼 필요가 있는 부분을 근거 사진과 함께 확인합니다.

실시간 분석은 촬영 후 분석으로 바꿨고, 음성 인식은 뒤로 미뤘습니다. 집에 자동으로 점수를 매기거나 계약할 집을 추천하는 기능도 뺐습니다. 원본 영상은 서버에 올리지 않고 휴대전화에만 남기도록 했습니다.

초기 체크리스트도 현장에서 28개 상태를 입력하는 방식 대신, 방문 전에 확인 방법을 익히는 가이드로 바꿨습니다. 현장에서는 기록에 집중하고, 촬영 후에 근거를 보는 쪽이 글래스의 장점과 더 잘 맞는다고 판단했습니다.

### 다음 장으로 넘기는 말

범위를 정한 뒤에는 팀이 같은 방향으로 움직이는 방법이 필요했습니다.

## 6. 한 달 동안 이렇게 움직였다

### 화면에 넣을 내용

큰 흐름:

`아이디어 정리 → MVP 결정 → 역할 분담 → 빠른 개발 → 테스트와 수정`

작게 표시할 작업 방식:

- Android·Meta·서버·AI 역할 분리
- Task 문서로 진행 상황 확인
- 기능 브랜치와 PR로 코드 통합
- OpenAPI로 앱과 서버의 약속 통일

### 발표 대본

한 달 동안은 이 순서로 움직였습니다.

먼저 아이디어를 모두 펼쳐 놓고 MVP에 남길 것과 미룰 것을 정했습니다. 그다음 Android, Meta 글래스, 서버, AI 영역을 나누고 각자 가까운 Task 문서에서 진행 상황을 관리했습니다.

코드는 기능별 브랜치에서 작업하고 PR을 통해 통합했습니다. 앱과 서버가 서로 다른 데이터 이름이나 상태값을 쓰지 않도록 OpenAPI 문서를 먼저 맞춘 뒤 구현했습니다.

개발 중에 실시간 분석이 현실적이지 않다고 판단했을 때도 문서만 바꾼 것이 아니라, Android·서버·데이터 계약을 함께 JPEG 분석 방식으로 변경했습니다.

## 7. 안경이 찍고, 앱이 챙기고, 내가 결정한다

### 화면에 넣을 내용

서비스 흐름:

`AI 글래스 → Android 앱 → API 서버 → AI 분석 → 확인 필요 결과`

반드시 함께 보여줄 세 문장:

- `원본 영상은 휴대전화에만`
- `서버에는 분석할 JPEG만`
- `AI는 하자를 확정하지 않음`

### 발표 대본

전체 흐름은 안경, Android 앱, 서버, AI 순서입니다.

안경은 서버와 직접 통신하지 않습니다. 사용자가 안경으로 촬영한 원본 영상은 휴대전화 갤러리에만 보관합니다. Android 앱은 촬영이 끝난 영상에서 일정 구간마다 JPEG 후보를 만들고, 그중 분석할 사진을 서버로 보냅니다.

서버는 매물과 임장, 사진의 처리 상태를 관리하고 AI 작업을 연결합니다. AI가 돌려주는 결과도 하자 판정이 아니라 `확인 필요 관찰 결과`입니다. 결과에는 반드시 어떤 사진을 보고 이야기했는지 근거가 붙습니다.

저희는 이 구조를 통해 글래스가 모든 것을 판단하는 서비스가 아니라, 사용자가 현장을 놓치지 않게 도와주는 서비스로 역할을 정했습니다.

### 다음 장으로 넘기는 말

설명보다 실제 화면을 보시는 게 더 빠를 것 같습니다.

## 8. 직접 보면 이런 느낌이다

### 화면에 넣을 내용

- 제목과 녹화 영상만 사용
- 영상 하단에 현재 단계 표시
- Mock 데이터가 나오는 구간에는 `시연용 데이터` 표시

### 60~90초 데모 구성표

| 구간 | 보여줄 화면 | 영상 자막 |
| --- | --- | --- |
| 0~8초 | 홈에서 점검 시작 | `오늘 확인할 매물을 선택합니다.` |
| 8~18초 | 매물 선택·등록 정보 | `매물별로 임장 기록을 나눠 관리합니다.` |
| 18~30초 | 점검 준비·권한 확인 | `촬영 전에 연결과 권한을 확인합니다.` |
| 30~45초 | 구역 가이드·촬영 화면 | `현관, 주방, 창문, 방, 욕실 순서로 둘러봅니다.` |
| 45~55초 | 촬영 종료 | `원본 영상은 휴대전화에 남습니다.` |
| 55~70초 | JPEG 생성·분석 진행 | `서버에는 분석할 JPEG만 보냅니다.` |
| 70~85초 | 관찰 결과·리포트 | `다시 볼 부분을 근거 사진과 확인합니다.` |

### 발표 대본

지금부터 사용자가 세입세잎으로 한 번의 임장을 진행하는 흐름을 짧게 보여드리겠습니다.

`[녹화 영상 재생]`

영상에서 보신 것처럼 사용자는 현장에서 복잡한 상태값을 계속 입력하지 않습니다. 촬영에 집중하고, 점검이 끝난 뒤 앱에서 구역별 사진과 다시 볼 부분을 확인합니다.

현재 영상의 분석 결과와 리포트 일부는 전체 경험을 보여드리기 위한 시연용 데이터입니다.

## 9. 한 달 동안 여기까지 만들었다

### 화면에 넣을 내용

화면 또는 테스트 근거와 함께 표시:

- Android 주요 화면과 이동 흐름
- 매물 등록·조회·수정·삭제
- 임장 시작·목록·상세·종료·취소 API
- 촬영 영상의 JPEG 추출·업로드 호출 흐름
- PostgreSQL 데이터 저장
- Android와 서버가 공유하는 OpenAPI 계약

### 발표 대본

한 달 동안 Android에서는 로그인과 온보딩부터 홈, 매물, 점검 준비, 구역 가이드, 촬영, 분석, 관찰 결과와 리포트까지 주요 화면 흐름을 구현했습니다.

그중 매물 등록·조회·수정·삭제는 Android 에뮬레이터에서 실제 서버와 연결해 확인했습니다. 서버에는 매물 API뿐 아니라 임장 시작, 목록, 상세 조회, 종료와 취소까지 이어지는 생명주기 API를 구현하고 PostgreSQL 통합 테스트를 진행했습니다.

촬영이 끝난 영상에서 JPEG를 추출하고 업로드 API를 호출하는 Android 흐름도 추가했습니다. 앱과 서버 사이의 요청과 응답은 OpenAPI 계약으로 관리했습니다.

다만 JPEG 업로드는 코드와 테스트가 추가된 상태이며, Meta 영상 가져오기부터 객체 저장소와 데이터베이스까지 연결되는 전체 과정은 아직 통합 검증이 남아 있습니다.

### 다음 장으로 넘기는 말

그래서 저희는 구현한 것과 아직 확인하지 못한 것을 따로 정리했습니다.

- 실제 AI 분석 결과 연결

반면 Meta 글래스에서 촬영한 영상을 가져와 JPEG를 만들고, 객체 저장소와 AI를 거쳐 다시 앱에 결과가 나타나는 전체 흐름은 아직 끝까지 검증하지 못했습니다. 실제 원룸에서의 현장 테스트와 개발자 도움 없이 이어지는 연속 데모도 남아 있습니다.

저희는 이 부분을 완성된 것처럼 포장하기보다, 다음 단계에서 가장 먼저 확인해야 할 과제로 두었습니다.

## 예상 질문과 답변

### 왜 스마트폰이 아니라 AI 글래스인가요?

스마트폰으로 촬영하면 한 손을 계속 사용해야 합니다. 글래스는 사용자가 문과 창문을 직접 열어 보고 집을 살피면서, 자신이 보는 장면을 함께 기록할 수 있다는 장점이 있습니다. 다만 글래스 연결이 실패해도 임장을 포기하지 않도록 휴대전화 촬영 대체 흐름도 후속 검증 대상입니다.

### 왜 실시간 AI 분석을 포기했나요?

한 달 안에 안정적으로 시연하기에는 SDK, 네트워크, 배터리와 영상 품질 변수가 컸습니다. 원본 스트림을 서버로 보내는 방식은 개인정보와 저장 비용 부담도 있습니다. 그래서 고화질 영상은 휴대전화에 남기고, 촬영 후 선별한 JPEG만 분석하는 방식으로 변경했습니다.

### AI가 하자를 잘못 판단하면 어떻게 하나요?

세입세잎은 AI 결과를 하자 판정으로 보여주지 않습니다. `확인 필요`라는 표현과 근거 사진을 함께 제공하고, 사용자가 다시 확인하거나 결과를 리포트에서 제외할 수 있도록 설계했습니다.

### 현재 AI가 실제로 연결되어 있나요?

현재 발표에서 보이는 분석 결과 일부는 전체 사용자 흐름을 보여주기 위한 시연용 데이터입니다. JPEG 업로드 계약과 Android 호출 흐름까지 구현했지만, 실제 AI Worker와 글래스 실기기를 포함한 전체 통합은 남아 있습니다.

### 개인정보는 어떻게 처리하나요?

원본 영상은 휴대전화 갤러리에만 보관하고 서버에는 올리지 않습니다. 서버에는 분석 대상으로 고른 JPEG와 필요한 메타데이터만 전달합니다. 실제 주소, 얼굴, 문서처럼 개인을 알아볼 수 있는 정보는 학습 데이터나 Git 저장소에 넣지 않는 것을 원칙으로 두고 있습니다.

### 한 달 동안 가장 크게 바뀐 점은 무엇인가요?

처음에는 현장에서 체크리스트 상태를 입력하고 실시간으로 AI 결과를 받는 구조였습니다. 개발 중에 사용자가 촬영과 입력을 동시에 하기 어렵고 기술 위험도 크다고 판단해, 촬영 후 근거 사진을 정리하는 구조로 바꾼 것이 가장 큰 변화입니다.

### 다른 부동산 앱과 무엇이 다른가요?

매물을 검색하거나 중개하는 서비스가 아니라, 사용자가 직접 집을 보러 간 순간의 기록을 돕는 서비스입니다. 글래스로 남긴 현장 영상에서 근거 사진을 정리하고, 다시 확인할 부분을 임장별로 남기는 데 집중합니다.

### 사업화한다면 누가 사용할 수 있나요?

처음에는 첫 자취를 준비하는 개인 사용자를 생각하고 있습니다. 실제 현장 검증과 AI 정확도 확인이 끝난 뒤에는 청년 주거 지원 기관, 임대주택 운영 기관, 주택 관리 분야에서 점검 기록을 정리하는 도구로 적용 가능한지 검토할 수 있습니다.
