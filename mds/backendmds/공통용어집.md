# 세입세잎 공통 용어집

프론트엔드, 백엔드, 기획, 디자인, 데이터 분석 담당자가 같은 대상을 같은 말로 부르기 위한 기준이다. 화면, 문서, API, 데이터베이스에서도 아래 의미를 동일하게 사용한다.

## 기본 용어

| 한글 용어 | 영문 표준명 | 설명 |
|---|---|---|
| 사용자 | `user` | 세입세잎 서비스에 가입하여 사용하는 사람 |
| 매물 | `property` | 사용자가 방문하거나 비교하려는 임대 주택 |
| 임장 | `inspection` | 특정 매물을 한 번 방문하여 점검하는 행위와 그 기록 |
| 체크리스트 | `checklist` | 임장 중 빠뜨리지 않고 확인해야 할 항목의 목록 |
| 촬영 프레임 | `frame` | 카메라로 촬영하여 AI 분석에 사용하는 한 장의 이미지 |
| AI 탐지 | `detection` | AI가 한 촬영 프레임에서 발견한 하나의 하자 후보와 그 위치 |
| 하자 종류 | ~~공란(미정)~~ → `label` | ~~데이터 분석 담당자가 확정한 뒤 작성~~ → AI가 탐지한 하자 후보를 아래 12개 중 하나로 구분한 값 |
| 신뢰도 | `confidence` | AI가 탐지 결과를 얼마나 확신하는지 나타내는 0~1 사이의 값. 안전 여부나 위험도와는 다름 |
| 바운딩 박스 | `bbox` | 이미지에서 하자 후보가 발견된 위치를 둘러싼 사각형 영역 |
| 메모 | `note` | 사용자가 임장 중 또는 임장 후 직접 남긴 기록 |
| 임장 리포트 | `report` | 임장 종료 후 촬영 자료, AI 탐지, 체크리스트, 메모를 모아 보여 주는 결과 |
| 기기 | `device` | 스마트 글래스나 스마트폰처럼 촬영에 사용하는 장치 |

## 하자 종류 12개

클래스 ID와 영문 레이블은 AI 모델이 사용하는 고정값이다. 코드와 데이터에서는 아래 영문 레이블의 철자와 소문자 표기를 그대로 사용한다.

| 클래스 ID | 영문 레이블 | 한글 표준명 | 설명 |
|---:|---|---|---|
| `0` | `crack` | 균열 | 벽, 천장 등 일반 표면에 갈라진 흔적이 있는 상태 |
| `1` | `mold` | 곰팡이 | 표면에 곰팡이로 의심되는 흔적이 있는 상태 |
| `2` | `peeling` | 도장·벽지 박리 | 페인트나 벽지가 표면에서 벗겨지거나 들뜬 상태 |
| `3` | `waterdamage` | 누수·침수 흔적 | 물로 인해 번짐, 변색 또는 손상 흔적이 생긴 상태 |
| `4` | `tiledamage` | 타일 파손 | 타일이 깨지거나 일부가 떨어져 나간 상태. 금만 간 상태인 `tilecrack`과 구분함 |
| `5` | `hole` | 타공·구멍 | 못, 나사, 장비 설치 등으로 표면에 구멍이 생긴 상태. 미세한 `pinhole`과 구분함 |
| `6` | `tilecrack` | 타일 균열 | 타일 표면에 금이 간 상태. 깨지거나 떨어져 나간 `tiledamage`와 구분함 |
| `7` | `paintdrips` | 페인트 흘러내림 | 흘러내린 페인트가 굳어 자국이 남은 상태 |
| `8` | `pinhole` | 핀홀 | 표면에 핀으로 찌른 것처럼 매우 작은 구멍이 생긴 상태 |
| `9` | `surfacedefect` | 면불량 | 표면이 고르지 않거나 마감 상태가 불량한 상태 |
| `10` | `stain` | 오염·얼룩 | 일반적인 오염이나 얼룩이 있는 상태. 물로 인한 흔적인 `waterdamage`와 구분함 |
| `11` | `trowelmark` | 흙손 자국 | 미장 작업에 사용한 흙손의 자국이 표면에 남은 상태 |

- `클래스 ID`는 학습 데이터와 모델 출력에서 사용하는 숫자이며 다른 의미로 재사용하지 않는다.
- `영문 레이블`은 API, AI 결과, 데이터 가공 과정에서 공통으로 사용하는 값이다.
- 한글 표준명은 화면과 문서에서 사용한다.
- AI 탐지는 하자 후보를 알려 주는 결과이며 실제 하자 또는 안전 문제를 확정하는 판정이 아니다.
- 분류의 이름, 순서 또는 의미가 바뀌면 용어 변경 규칙에 따라 기존 표현에 취소선을 남기고 모델·API·데이터의 호환 범위를 함께 확인한다.

## 꼭 필요한 추가 용어

| 한글 용어 | 영문 표준명 | 설명 |
|---|---|---|
| AI 분석 | `analysis` | AI가 촬영 프레임을 살펴보고 탐지 결과를 만드는 과정 |
| 위험도 | `risk_level` | 정해진 기준에 따라 사용자에게 주의를 알리는 표시 단계. 신뢰도와 같은 뜻이 아님 |
| 매물 비교 | `comparison` | 둘 이상의 임장 리포트를 같은 기준으로 나란히 확인하는 기능과 그 결과 |

## 사용 원칙

- 한 대상에는 이 문서의 한글 용어와 영문 표준명만 사용한다.
- `임장`은 매물 한 곳을 한 번 점검한 단위이며, 같은 매물을 다시 점검하면 별도의 임장으로 본다.
- `AI 탐지`는 하자 후보를 알려 주는 보조 정보다. 안전, 계약 적합성 또는 하자 없음을 확정하는 판정으로 사용하지 않는다.
- `신뢰도`는 AI 모델의 확신 정도이고, `위험도`는 별도 기준으로 만든 사용자 안내 단계다. 두 값을 서로 바꾸어 쓰지 않는다.
- 확정되지 않은 용어와 분류 값은 임의로 채우지 않는다.

## 용어 변경 규칙

용어의 이름이나 의미를 확대·축소할 때 기존 내용을 조용히 지우지 않는다.

1. 변경할 표의 기존 표현에 취소선을 긋고 새 표현을 바로 뒤에 적는다.
   - 이름 변경: ~~기존 용어~~ → 새 용어
   - 의미 변경: ~~기존 설명~~ → 새 설명
2. 변경 전 표현을 사용하는 화면, 문서, API, 데이터베이스가 있는지 확인하고 함께 바꿀 범위를 정한다.
3. 이미 배포된 이름을 즉시 없애야 한다면 데이터 호환 방법과 적용 날짜를 먼저 정한다.
4. 아래 변경 이력에 날짜, 변경 내용, 이유를 기록한다.
5. `하자 종류`는 데이터 분석 담당자가 확정한 내용만 반영한다.
