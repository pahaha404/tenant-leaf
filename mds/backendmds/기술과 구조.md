# 세입세잎 MVP 기술과 구조

이 문서는 `개발 순서.md`의 **2. 기술과 구조 정하기** 단계에서 사용할 최소 구성이다. 첫 단계에서는 서버와 데이터베이스가 로컬에서 실행되는 것까지만 만든다. 사진 저장소, AI 작업 큐, 클라우드 배포는 실제로 필요한 단계가 왔을 때 추가한다.

## 한눈에 보는 결정

| 구분 | MVP 기본 구조에서 사용할 것 | 쉽게 설명하면 |
|---|---|---|
| 서버 언어 | Kotlin, JDK 21 LTS | 서버 프로그램을 작성하는 언어와 장기 지원 실행 환경 |
| 서버 프레임워크 | Spring Boot | 로그인, 매물, 임장 같은 API를 만드는 기본 틀 |
| 빌드·테스트 | Gradle | 서버 실행과 자동 테스트를 맡는 도구 |
| 데이터베이스 | PostgreSQL | 사용자, 매물, 임장 정보를 표 형태로 보관하는 곳 |
| 로컬 실행 | Docker Compose | 팀원이 같은 설정으로 PostgreSQL을 실행하게 하는 도구 |
| DB 구조 관리 | Flyway | 빈 데이터베이스를 같은 구조로 만들어 주는 변경 기록 |
| 상태 확인 | Spring Boot Actuator | 서버와 데이터베이스가 정상인지 확인하는 기능 |
| 로컬 비밀 정보 | Git에 올리지 않는 `.env` | 비밀번호와 키를 코드 밖에 두는 방법 |

**기본 구조의 결론:** 지금은 `Kotlin + Spring Boot + PostgreSQL` 한 조합만 실행 가능하게 만든다.

## 지금 만들 구조

```text
개발자 컴퓨터
  ├─ Spring Boot API
  │    └─ 사용자·매물·임장 등의 정보를 읽고 저장
  └─ Docker PostgreSQL
       └─ 서비스 데이터 보관
```

이 단계에서는 Android 앱, 실제 사진 업로드, AI 분석까지 연결하지 않는다. 먼저 서버와 데이터베이스라는 가장 작은 기반을 안정적으로 실행한다.

## 기본 구조에 포함할 기능

- `services/api`의 Gradle 기반 Spring Boot 프로젝트
- PostgreSQL 연결 설정
- Docker Compose 기반 로컬 PostgreSQL
- Flyway 초기 마이그레이션
- `/actuator/health` 상태 확인
- 애플리케이션 시작 테스트와 데이터베이스 연결 테스트
- `.env.example`과 실제 비밀 정보 제외 설정
- 새 팀원이 따라 할 수 있는 실행 README
- 빌드와 테스트를 실행하는 최소 CI

## 지금 사용하지 않을 것

- Redis 또는 별도 캐시
- Pub/Sub 같은 메시지 큐
- Kubernetes
- 여러 개의 데이터베이스
- 실제 AI 제공자 연동
- 실제 촬영 파일 업로드
- Cloud Run, Cloud SQL 같은 유료 클라우드 자원
- 운영용 모니터링과 자동 확장 설정

필요성이 확인되지 않은 도구를 미리 추가하면 설치, 오류 확인, 비용 관리 대상만 늘어난다. 기본 구조가 실행된 뒤 다음 기능에 필요한 도구만 한 번에 하나씩 추가한다.

## 나중에 추가하는 순서

### 1. 사진 업로드를 만들 때

사진 원본을 데이터베이스에 넣지 않고 파일 저장소를 추가한다. 배포 전 로컬 테스트에서는 가짜 저장소나 테스트용 파일로 흐름을 확인하고, 외부 환경이 필요할 때 비공개 Cloud Storage 사용 여부를 확정한다.

### 2. 가짜 AI 흐름을 만들 때

먼저 PostgreSQL에 AI 작업 상태와 가짜 관찰 결과를 저장한다. 별도 메시지 큐 없이도 첫 흐름을 검증할 수 있게 만들고, 처리량이나 재시도 요구가 확인된 뒤 작업 큐 도입 여부를 결정한다.

AI 결과는 항상 근거 미디어가 있는 `확인 필요 관찰 결과`로 저장한다. 최종 체크리스트 상태는 Android 앱에서 사용자가 확정한다.

### 3. 외부에서 접속할 서버가 필요할 때

로컬 데모가 성공하고 비용 담당자가 승인한 뒤 아래 운영 기술을 검토한다.

- API와 AI 작업자 배포: Cloud Run
- 운영 PostgreSQL: Cloud SQL
- 촬영 파일: 비공개 Cloud Storage
- 운영 비밀 정보: Secret Manager
- 기본 리전 후보: 서울 `asia-northeast3`

이 목록은 지금 생성할 자원이 아니라 배포 단계의 후보이다. 개발·스테이징·운영 환경 분리, 비용, 계정 소유자, 촬영 자료 보관 기간을 정하기 전에는 유료 자원을 만들지 않는다.

## 기본 구조 작업 순서

1. JDK 21과 Docker Desktop 설치 상태를 확인한다.
2. `services/api`에 Spring Boot 프로젝트를 만든다.
3. Docker Compose로 PostgreSQL을 실행한다.
4. Spring Boot가 PostgreSQL에 연결되게 한다.
5. Flyway로 빈 데이터베이스에 초기 구조를 만든다.
6. `/actuator/health`에서 서버와 DB 상태를 확인한다.
7. 자동 테스트와 CI에서 같은 결과가 나오는지 확인한다.
8. README만 보고 다른 팀원이 다시 실행해 본다.

## 완료 기준

- 새 팀원이 README만 보고 서버와 PostgreSQL을 실행할 수 있다.
- 빈 PostgreSQL을 실행해도 Flyway가 같은 DB 구조를 만든다.
- `/actuator/health`가 서버와 DB의 정상 상태를 보여 준다.
- 자동 테스트와 CI가 통과한다.
- 비밀번호, 토큰, 실제 개인정보가 Git에 포함되지 않는다.
- 클라우드 계정이나 실제 AI 키가 없어도 기본 구조를 검증할 수 있다.

## 다음 기능으로 넘어가는 기준

기본 구조의 완료 기준을 모두 확인한 뒤 아래 순서로 진행한다.

```text
공통 API 계약 → 사용자 확인 → 매물 → 임장 → 사진 한 장 → 가짜 AI → 사용자 확정 → 리포트
```

한 단계가 실행되고 테스트된 뒤 다음 단계에 필요한 기술만 추가한다.
