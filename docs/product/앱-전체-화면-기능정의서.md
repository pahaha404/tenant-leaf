# 세입세잎 앱 전체 화면 기능정의서

## 1. 문서 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 세입세잎 MVP의 핵심 사용자 여정을 화면 단위로 정의하고 디자인·Android·API·AI 작업의 공통 기준으로 사용한다. |
| 범위 | 앱 시작부터 로그인, 온보딩, 현장 점검, 사용자 확인, 리포트, 매물 비교까지의 `00~11` 화면 |
| 플랫폼 | Android 앱 |
| 상태 | 화면 설계 기준 초안 |
| 작성일 | 2026-08-11 |

이 문서는 정보 구조와 기능 동작을 정의한다. 색상·글꼴·간격은 디자인 시스템에서, API 필드와 상태값은 공통 계약 문서에서 최종 확정한다.

## 2. 서비스 원칙

- 데이터 흐름은 `Meta 안경 -> Android 앱 -> API -> AI 작업자` 순서를 지킨다.
- Meta 안경은 서버나 AI 제공자를 직접 호출하지 않는다.
- AI는 하자나 안전 상태를 확정하지 않고 사진에 근거한 `확인 필요 관찰 후보`만 제안한다.
- 최종 체크 상태는 사용자가 `문제 없음`, `문제 있음`, `확인 못함` 중 하나로 선택한다.
- 리포트의 사실은 사용자 입력, 사진, 녹음 또는 STT 문장과 연결한다.
- 근거가 없거나 확인하지 못한 내용은 추정하지 않고 `미확인`으로 표시한다.
- 매물 비교는 점수, 자동 순위, 계약 추천 없이 사실을 나란히 보여 준다.
- 연결 또는 네트워크 문제가 생겨도 작성 내용과 촬영 대기 데이터는 보존한다.

## 3. 전체 화면 흐름

```text
00-1 로딩
  ├─ 최초 사용자 ─> 00-2 첫 접속 ─> 00-3 로그인 ─> 01 온보딩 ─> 02 홈
  ├─ 기존 로그인 사용자 ───────────────────────────────> 02 홈
  └─ 로그아웃 사용자 ─────────────────────> 00-3 로그인 ─> 02 홈

02 홈
  ├─ 새 점검 시작
  │    └─> 03 매물 등록
  │          └─> 04 점검 준비
  │                └─> 05 실시간 점검
  │                      ├─> 06 체크리스트 ───────────────┐
  │                      ├─> 08 녹음·STT ────────────────┤
  │                      └─ 점검 마치기                   │
  │                            └─> 06 체크리스트 최종 확인 │
  │                                  └─> 07 증거 사진 검토 │
  │                                        └─> 08 녹음·STT 확인
  │                                              └─> 09 처리 현황
  │                                                    └─> 10 임장 리포트
  │                                                          └─> 11 매물 비교
  ├─ 진행 중 점검 ─> 저장된 진행 단계로 복귀
  └─ 기존 리포트 보기 ─> 10 임장 리포트 ─> 11 매물 비교
```

`00`은 앱 진입 단계이므로 `00-1 로딩`, `00-2 첫 접속`, `00-3 로그인`으로 구분한다. 권한 요청, 종료 확인, 연결 실패, 업로드 실패 등은 독립 페이지가 아니라 해당 화면의 모달·바텀시트·오류 상태로 관리한다.

## 4. 페이지별 설계표

| 번호 | 화면 | 목적 | 주요 내용 | 가장 중요한 버튼 |
| --- | --- | --- | --- | --- |
| 00-1 | 로딩 | 앱 시작 상태 확인 | 로고, 초기화, 로그인·온보딩 완료 여부 | 없음 |
| 00-2 | 첫 접속 | 서비스 가치 소개 | 캐릭터, 서비스 설명, 핵심 이점 | 시작하기 |
| 00-3 | 로그인 | 계정 진입 | 카카오 로그인, 이메일 로그인 | 로그인하기 |
| 01 | 온보딩 | 사용 방법과 책임 범위 안내 | 안경 촬영, AI 보조, 사용자 최종 확인 | 다음 |
| 02 | 홈 | 다음 점검 행동 시작 | 연결 상태, 진행 중 점검, 새 점검, 기존 리포트 | 점검 이어하기 또는 새 점검 시작 |
| 03 | 매물 등록 | 점검 대상 정보 입력 | 매물명, 주소, 주거 형태, 방문 일정 | 체크리스트 선택하기 |
| 04 | 점검 준비 | 장비·권한·항목 확인 | 안경, 휴대폰, 권한, 체크리스트 | 점검 시작하기 |
| 05 | 실시간 점검 | 현장 촬영과 구역 진행 | 현재 구역, 촬영, 배터리, 연결, 진행률 | 점검 마치기 |
| 06 | 체크리스트 | 사용자가 항목 상태 확정 | 구역별 항목, 상태, 메모, 사진, AI 관찰 | 다음 항목 확인하기 |
| 07 | 증거 사진 검토 | 리포트에 쓸 사진 확정 | AI 사진 후보, 관찰 후보, 제외·교체 | 선택한 사진 확정 |
| 08 | 녹음·STT 확인 | 중개인 설명 기록과 문장 교정 | 녹음, 파형, STT, 문장 수정·삭제 | 점검 마무리하기 |
| 09 | 처리 현황 | 비동기 결과 생성 상태 안내 | 업로드, AI 관찰, STT, 리포트 단계 | 결과 확인하기 |
| 10 | 임장 리포트 | 근거 중심 결과 확인 | 사용자 확인, 사진 근거, 미확인, STT 메모 | 내용 수정 |
| 11 | 매물 비교 | 2~3개 매물의 사실 비교 | 비용, 채광, 수압, 누수, 미확인, 사진 | 상세 리포트 보기 |

## 5. 공통 화면 규칙

### 5.1 이동과 저장

- 이전 단계로 돌아갈 수 있는 화면에는 뒤로가기를 제공한다.
- 점검 중에는 매물명 또는 현재 구역과 전체 진행률을 표시한다.
- 입력 화면에서 뒤로갈 때 현재 내용을 자동 임시 저장한다.
- 저장 실패 시 화면을 닫기 전에 원인, 데이터 보존 여부, 재시도 방법을 보여 준다.
- 한 화면에는 가장 중요한 주요 버튼을 한 개만 강조한다.
- 필수 입력이 끝나지 않으면 주요 버튼을 비활성화하고 부족한 항목을 안내한다.
- 처리 중에는 중복 요청을 막고 로딩 상태를 표시한다.

### 5.2 상태 표현

| 의미 | 표시 원칙 |
| --- | --- |
| 사용자 확인 완료 | 체크 아이콘과 `사용자 확인` 문구를 함께 표시 |
| AI 관찰 후보 | AI 배지와 `직접 확인 필요` 문구를 표시 |
| 미확인 | 회색 상태와 `확인 못함` 문구를 표시 |
| 처리 중 | 단계명, 진행 표시, 앱을 나가도 되는지 안내 |
| 실패 | 실패한 대상, 데이터 보존 여부, 재시도 방법을 표시 |

색상만으로 상태를 구분하지 않고 아이콘과 텍스트를 함께 사용한다.

### 5.3 데이터 보존

- 매물 입력, 체크리스트 선택, 메모, 사진 선택, STT 수정 내용은 단계 이동 시 저장한다.
- 네트워크가 없으면 로컬에 임시 저장하고 연결 회복 후 재전송한다.
- 업로드 대기와 서버 처리 대기를 구분해서 표시한다.
- 사용자가 명시적으로 삭제하기 전에는 연결 실패만으로 점검 데이터를 지우지 않는다.

## 6. 화면별 상세 기능 정의

### 6.1 `00-1` 로딩

| 구분 | 정의 |
| --- | --- |
| 진입 조건 | 앱 실행, 로그아웃 후 재실행, 앱 복귀 중 세션 재확인이 필요할 때 |
| 표시 내용 | 브랜드 로고, 로딩 상태 |
| 시스템 처리 | 앱 초기화, 로그인 토큰, 최초 접속·온보딩 완료 여부, 진행 중 점검 확인 |
| 정상 이동 | 최초 사용자는 `00-2`, 로그아웃 사용자는 `00-3`, 기존 로그인 사용자는 `02` |
| 예외 상태 | 로컬 정보를 먼저 확인하고 서버 확인이 꼭 필요한 경우 `다시 시도` 표시 |

수 초 이상 지연되면 `정보를 불러오는 중이에요`와 진행 표시를 보여 준다.

### 6.2 `00-2` 첫 접속

| 구분 | 정의 |
| --- | --- |
| 진입 조건 | 최초 설치 후 처음 실행하거나 첫 접속 안내를 완료하지 않은 사용자 |
| 표시 내용 | 세잎이 캐릭터, 서비스 소개, `안경으로 기록`, `AI가 정리 보조`, `내가 최종 확인` |
| 주요 버튼 | `시작하기` |
| 버튼 동작 | 첫 접속 안내 완료 상태를 저장하고 `00-3 로그인`으로 이동 |
| 보조 기능 | 개인정보 처리 안내와 이용약관 링크 |

AI가 집의 하자를 대신 판정한다는 표현을 사용하지 않는다.

### 6.3 `00-3` 로그인

| 구분 | 정의 |
| --- | --- |
| 진입 조건 | 첫 접속 안내 완료, 기존 사용자 로그아웃, 로그인 토큰 만료 |
| 표시 내용 | 카카오 로그인, 이메일 로그인, 약관 링크 |
| 입력 검증 | 이메일 형식, 비밀번호, 로그인 방식 선택 여부 |
| 정상 이동 | 최초 로그인 사용자는 `01`, 온보딩 완료 사용자는 `02` |
| 오류 상태 | 인증 취소, 계정 불일치, 네트워크 오류를 구분해 재시도 제공 |

### 6.4 `01` 온보딩

| 단계 | 제목 | 핵심 설명 | 행동 |
| --- | --- | --- | --- |
| 1 | 안경으로 편하게 기록해요 | Meta 안경 또는 휴대폰으로 점검 사진을 남긴다. | 다음 |
| 2 | AI가 확인할 곳을 제안해요 | AI는 사진 속 관찰 후보와 대표 사진을 제안한다. | 다음 |
| 3 | 최종 판단은 내가 해요 | 체크 상태와 리포트 포함 여부는 사용자가 확정한다. | 시작하기 |

- 페이지 표시와 `건너뛰기`를 제공한다.
- 마지막 단계 완료 시 상태를 저장하고 `02 홈`으로 이동한다.
- 카메라·마이크·위치 권한은 기능을 시작하는 시점에 요청한다.
- 설정 또는 도움말에서 다시 볼 수 있어야 한다.

### 6.5 `02` 홈

| 상태 | 표시 내용 |
| --- | --- |
| 기본 | 인사말, 안경 연결 상태, 새 점검, 최근 리포트, 빠른 메뉴 |
| 진행 중 점검 있음 | 매물명, 현재 구역, 경과 시간, 체크 진행률, 업로드 대기, `점검 이어하기` |
| 진행 중 점검 없음 | `새 점검 시작`을 가장 크게 표시 |
| 리포트 있음 | 최근 리포트 카드와 `전체 리포트 보기` |
| 빈 상태 | `아직 저장한 매물이 없어요`와 `첫 점검 시작` |

| 버튼 | 동작 |
| --- | --- |
| 점검 이어하기 | 저장된 세션의 단계에 따라 `04~09` 중 해당 화면으로 복귀 |
| 새 점검 시작 | `03 매물 등록`으로 이동 |
| 기존 리포트 보기 | 리포트 목록에서 선택 후 `10 임장 리포트`로 이동 |
| 안경 연결 상태 | 연결 상세 바텀시트에서 연결, 해제, 다시 시도 |
| 매물 비교 | 리포트가 2개 이상이면 `11`, 아니면 필요한 매물 수 안내 |

### 6.6 `03` 매물 등록

| 필드 | 필수 | 기능 및 검증 |
| --- | --- | --- |
| 매물명 | 예 | 목록과 리포트에서 구분할 이름. 공백만 입력 불가 |
| 주소 | 예 | 주소 검색 또는 직접 입력 후 사용자가 최종 확인 |
| 주거 형태 | 예 | 원룸, 투룸, 오피스텔, 빌라 등 선택형 |
| 방문 일정 | 아니요 | 날짜·시간 입력. 과거 시간은 확인 안내 |
| 개인 메모 | 아니요 | 중개인 연락, 확인할 조건 등 자유 입력 |

| 버튼 | 동작 |
| --- | --- |
| 체크리스트 선택하기 | 필수 입력 검증 후 매물을 저장하고 체크리스트 선택 또는 `04`로 이동 |
| 임시 저장 | 입력 내용만 저장하고 `02`로 이동 |
| 취소 | 입력 내용이 있으면 폐기 여부를 확인한 뒤 이전 화면으로 이동 |

기본값은 모든 구역을 포함한 `필수 점검` 체크리스트다.

### 6.7 `04` 점검 준비

| 준비 항목 | 완료 조건 | 미완료 시 행동 |
| --- | --- | --- |
| 스마트글라스 | 연결됨, 배터리 확인 | 다시 연결, 도움말, 휴대폰으로 계속 |
| 휴대폰 | 저장 공간과 네트워크 확인 | 저장 공간 정리 또는 오프라인 저장 안내 |
| 카메라 권한 | 허용됨 | 권한 요청, 설정으로 이동 |
| 마이크 권한 | 녹음 사용 시 허용 | 권한 요청, 녹음 없이 계속 |
| 위치 권한 | 위치 저장 선택 시 허용 | 권한 요청, 위치 없이 계속 |
| 체크리스트 | 1개 이상 항목 선택 | 체크리스트 편집 |
| 촬영 안내 | 촬영·녹음 사실 안내 확인 | 안내 다시 보기 |

- `점검 시작하기`는 필수 준비가 끝나면 방문 세션을 생성하고 `05`로 이동한다.
- 안경 연결 실패 시에도 휴대폰 촬영 모드로 시작할 수 있다.
- 녹음과 위치는 선택 기능이므로 거부해도 점검을 막지 않는다.

### 6.8 `05` 실시간 점검

| 영역 | 표시 내용 |
| --- | --- |
| 상단 상태 | 뒤로가기, 매물명, 안경 연결, 배터리, 네트워크 |
| 현재 구역 | 현관·방·창문·욕실·주방·거실 중 현재 구역 |
| 촬영 상태 | 촬영 중·일시정지·연결 끊김, 최근 촬영 성공 여부 |
| 진행 정보 | 완료 항목 수 / 전체 항목 수, 현재 구역 진행률 |
| 음성 안내 | 지금 확인할 행동 한 문장, 다시 듣기 |
| 빠른 행동 | 중요 사진 촬영, 체크리스트, 녹음, 구역 변경 |
| 종료 | `점검 마치기` |

- 구역 자동 인식은 제안으로만 사용하며 사용자가 언제든 바꿀 수 있다.
- 구역을 인식하지 못하면 구역 선택 바텀시트를 연다.
- 촬영 성공은 진동·아이콘·텍스트로 함께 알린다.
- 안경 연결이 끊기면 세션을 유지하고 `다시 연결`과 `휴대폰으로 계속`을 제공한다.
- 앱이 백그라운드로 가도 세션과 촬영 대기 목록을 보존한다.
- `점검 마치기`를 누르면 미확인 수를 보여 주고 `계속 확인하기`와 `검토로 이동`을 제공한다.

### 6.9 `06` 체크리스트

#### 화면 구조

```text
[뒤로가기]      {현재 구역}      {완료 수} / {전체 수}

직접 확인한 내용을 선택해주세요

┌──────────────────────────────┐
│ {점검 항목명}                 │
│ [문제 없음] [문제 있음] [확인 못함] │
│ [메모 추가]           [사진 보기] │
│ AI 관찰 후보: {중립적 설명}       │  선택적으로 표시
└──────────────────────────────┘

AI는 관찰 후보만 제안하며 최종 상태는 사용자가 선택해요.

[다음 항목 확인하기]
```

| 상태 | 의미 | 후속 처리 |
| --- | --- | --- |
| 문제 없음 | 사용자가 직접 확인했고 문제를 발견하지 못함 | 없음 |
| 문제 있음 | 사용자가 문제 또는 재확인 필요 상태를 확인함 | 메모나 사진 연결 권장 |
| 확인 못함 | 시간, 접근, 장비 등의 이유로 확인하지 못함 | 리포트의 미확인 항목에 포함 |
| 미선택 | 아직 상태를 선택하지 않음 | 완료 수에 포함하지 않음 |

AI 관찰 후보가 있어도 사용자 상태를 자동 선택하지 않는다.

| 기능 | 동작 |
| --- | --- |
| 상태 선택 | 한 항목에서 하나만 선택하며 언제든 변경 가능 |
| 메모 추가 | 입력·수정·삭제, 자동 임시 저장 |
| 사진 보기 | 항목 사진과 AI 후보를 보고 연결·해제 |
| AI 관찰 보기 | 중립적 관찰 문구, 근거 사진, 직접 확인 안내 |
| 다음 항목 확인하기 | 다음 미완료 항목 또는 다음 구역으로 이동 |
| 뒤로가기 | 변경 내용을 저장하고 실시간 점검으로 복귀 |

#### 재사용 가능한 구역 템플릿

`06`은 주방 전용 화면이 아니라 `구역 정보 + 점검 항목 목록`을 받아 그리는 공통 템플릿으로 구현한다.

| 구역 | 주요 체크 항목 |
| --- | --- |
| 현관 | 현관문, 도어락, 신발장, 벽 |
| 방 | 천장, 벽, 바닥, 콘센트, 에어컨 |
| 창문 | 창틀, 방충망, 개폐, 실리콘 |
| 욕실 | 수압, 배수구, 환풍기, 곰팡이, 누수 |
| 주방 | 싱크대, 수압, 배수, 곰팡이·누수, 가스레인지 |
| 거실 | 바닥, 벽, 창문, 채광, 콘센트 |

구역명, 항목명, 설명, 중요도, 안내 문구는 화면 코드에 직접 고정하지 않고 체크리스트 설정에서 불러온다.

### 6.10 `07` 증거 사진 검토

| 구분 | 정의 |
| --- | --- |
| 표시 단위 | 구역별 또는 체크 항목별 사진 묶음 |
| 사진 정보 | 썸네일, 촬영 시각, 촬영 기기, 연결 구역·항목, AI 관찰 여부 |
| 선택 상태 | 리포트 포함, 제외, 교체 필요 |
| 빈 상태 | 사진이 없는 항목과 `사진 없이 계속` 또는 `다시 촬영` 안내 |

| 버튼 | 동작 |
| --- | --- |
| 선택한 사진 확정 | 결과를 저장하고 `08`로 이동 |
| 사진 크게 보기 | 원본 비율 미리보기와 이전·다음 탐색 |
| 이 사진 사용 | 대표 또는 근거 사진으로 선택 |
| 리포트에서 제외 | 원본 삭제가 아니라 리포트 연결만 해제 |
| 사진 교체 | 같은 항목의 다른 사진 선택 또는 재촬영 안내 |
| 직접 확인 필요 | `06`의 해당 항목으로 이동 |

AI 사진은 기본 후보일 뿐이며 사용자가 제외하거나 바꿀 수 있다.

### 6.11 `08` 녹음·STT 확인

| 영역 | 기능 |
| --- | --- |
| 녹음 제어 | 녹음 시작, 일시정지, 종료, 재생, 삭제 |
| 녹음 상태 | 녹음 시간, 파형, 입력 마이크, 저장 여부 |
| STT 문장 | 시간대별 변환 문장, 처리 중·성공·실패 상태 |
| 문장 편집 | 오인식 문장 수정, 삭제, 중요 표시 |
| 근거 연결 | 문장을 매물 정보나 체크 항목에 연결 |

- 녹음 시작 전에 촬영·녹음 사실 안내 확인을 표시한다.
- 원본 STT와 사용자가 수정한 최종 문장을 구분해 저장한다.
- STT 실패 시 원본 녹음이 있으면 재변환을 제공한다.
- 원본 녹음이 없으면 STT 문장을 녹음 근거처럼 표시하지 않는다.
- `점검 마무리하기`는 저장 상태 확인 후 `09`로 이동한다.
- 녹음이 없어도 점검을 마무리할 수 있다.

### 6.12 `09` 처리 현황

| 단계 | 상태 | 화면 동작 |
| --- | --- | --- |
| 미디어 업로드 | 대기·진행 중·완료·일부 실패·실패 | 실패 파일만 재시도하거나 제외 |
| AI 관찰 | 대기·진행 중·완료·실패 | AI 결과 없이 리포트 계속 생성 가능 |
| STT 변환 | 해당 없음·대기·진행 중·완료·실패 | 원본 녹음이 있으면 재시도 |
| 리포트 생성 | 대기·진행 중·완료·실패 | 사용 가능한 데이터로 재생성 |

- 필수 단계가 끝나면 `결과 확인하기`를 활성화하고 `10`으로 이동한다.
- 앱을 닫아도 처리가 계속되는지 안내하고 `홈으로 이동`을 제공한다.
- 처리 상태는 홈의 진행 카드에서도 확인할 수 있다.
- AI 또는 STT 실패는 리포트 확인을 무조건 막지 않고 누락 영역을 표시한다.
- 업로드되지 않은 사진은 리포트 근거로 표시하지 않는다.

### 6.13 `10` 임장 리포트

#### 정보 구조

1. 매물 기본 정보: 매물명, 주소, 주거 형태, 방문 일시
2. 점검 요약: 사용자 확인 완료 수, 문제 있음 수, 확인 못함 수
3. 구역별 결과: 항목 상태, 사용자 메모, 사진 근거
4. AI 관찰 후보: 근거 사진과 사용자 확인 여부
5. 중개인 설명: 사용자가 확정한 STT 문장과 원본 녹음
6. 미확인 항목: 이번 방문에서 확인하지 못한 내용
7. 다시 확인할 내용: 사용자가 직접 추가·수정한 메모

| 버튼 | 동작 |
| --- | --- |
| 내용 수정 | 체크 상태, 메모, 사진 연결, STT 문장 편집 |
| 근거 사진 보기 | 해당 문장의 연결 사진 확대 |
| 녹음 듣기 | 해당 STT 문장의 원본 시간대로 이동해 재생 |
| 매물 비교 | 현재 매물을 포함해 `11`로 이동 |
| 미확인만 보기 | 확인 못함과 근거 누락 항목만 표시 |

- AI 확정 문구, 근거 없는 자동 요약, 종합 점수, 자동 추천, 계약 판단을 제공하지 않는다.
- 사용자가 수정한 내용과 AI 제안을 시각적으로 구분한다.

### 6.14 `11` 매물 비교

| 구분 | 정의 |
| --- | --- |
| 비교 수 | 기본 2개, 최대 3개 |
| 선택 조건 | 리포트가 생성된 매물 우선. 처리 중 매물은 상태 표시 |
| 기본 비교 | 보증금, 월세, 관리비, 주거 형태, 방문 일시 |
| 현장 비교 | 채광, 수압, 배수, 곰팡이·누수 흔적, 창문, 미확인 수 |
| 근거 | 각 값에 사용자 확인 또는 대표 사진 연결 |
| 사용자 기록 | 별표, 장점, 단점, 다시 확인할 내용 |

| 버튼 | 동작 |
| --- | --- |
| 상세 리포트 보기 | 선택한 매물의 `10`으로 이동 |
| 매물 교체 | 비교 대상 선택 바텀시트 표시 |
| 차이만 보기 | 값이나 상태가 다른 행만 표시 |
| 미확인만 보기 | 한 매물이라도 확인 못한 항목만 표시 |
| 사진 크게 보기 | 비교 맥락을 유지한 채 근거 사진 표시 |
| 개인 메모 추가 | 비교 판단을 위한 사용자 메모 저장 |

데이터가 없는 셀은 `정보 없음`으로 표시하며 다른 값으로 추정하지 않는다.

## 9. 핵심 상태 전이

```text
점검 세션
준비 전 -> 준비 완료 -> 점검 중 -> 검토 중 -> 처리 중 -> 리포트 완료
                         ├-> 일시정지
                         └-> 연결 끊김 후 복구

체크 항목
미선택 -> 문제 없음 / 문제 있음 / 확인 못함 -> 사용자 수정 가능

미디어
로컬 저장 -> 업로드 대기 -> 업로드 중 -> 업로드 완료
                             └-> 실패 -> 재시도 또는 제외

AI 관찰
처리 전 -> 처리 중 -> 관찰 후보 생성 -> 사용자 확인
                    └-> 실패 -> AI 결과 없이 계속
```

## 10. 오류·빈 상태

| 상황 | 필수 안내 | 가능한 행동 |
| --- | --- | --- |
| 네트워크 없음 | 로컬 저장 여부와 제한 기능 | 계속 점검, 다시 시도 |
| 안경 연결 실패 | 점검 데이터 유지 | 다시 연결, 휴대폰으로 계속 |
| 배터리 부족 | 중단 위험 | 충전 안내, 휴대폰 모드 |
| 카메라 권한 거부 | 촬영 제한 이유 | 다시 요청, 설정 이동 |
| 마이크 권한 거부 | 녹음·STT 사용 불가 | 녹음 없이 계속, 설정 이동 |
| 업로드 실패 | 실패 파일 수와 보존 위치 | 다시 시도, 제외하고 계속 |
| AI 결과 없음 | 사용자 결과는 유지됨 | 다시 시도, AI 없이 리포트 보기 |
| STT 실패 | 원본 녹음 저장 여부 | 재변환, 직접 메모, 삭제 |
| 리포트 없음 | 생성 전 또는 실패 원인 | 처리 현황, 다시 생성 |
| 비교 대상 부족 | 최소 2개 리포트 필요 | 다른 리포트 선택, 새 점검 |

## 11. 접근성·사용성

- 주요 버튼 터치 영역은 최소 `48dp`, 점검 중 핵심 버튼은 `64dp` 이상을 권장한다.
- 본문은 `15~16sp` 이상을 기본으로 하고 시스템 글자 크기 확대를 지원한다.
- 촬영 성공, 연결 끊김, 중요 오류는 색상 외에 아이콘, 문구, 진동을 함께 사용한다.
- `문제 없음`과 `문제 있음`은 오선택을 줄이도록 충분한 간격을 둔다.
- 점검 중 다음 행동을 한 문장으로 안내한다.
- 녹음·사진·점검 삭제는 재확인한다.
- 로딩 중에도 현재 단계와 기다리는 이유를 표시한다.

## 12. 화면 완료 기준

- 기본, 로딩, 빈 상태, 오류, 비활성, 처리 중 상태가 디자인되어 있다.
- 주요 버튼의 이동 대상과 뒤로가기 결과가 정의되어 있다.
- 읽고 저장할 데이터가 정의되어 있다.
- 네트워크, 권한, 안경 연결 실패 시 데이터 보존 방식이 확인된다.
- AI 관찰 후보와 사용자 최종 확인이 혼동되지 않는다.
- Android 에뮬레이터 또는 실기기에서 화면과 주요 이동을 직접 확인한다.
- 공통 상태값은 API·데이터 모델과 일치한다.

## 13. 구현 우선순위

1. `00~03`: 앱 진입, 온보딩, 홈, 매물 등록
2. `04~06`: 점검 준비, 실시간 점검, 재사용 체크리스트
3. `07~09`: 증거 사진, 녹음·STT, 처리 현황
4. `10~11`: 임장 리포트, 매물 비교
5. 권한 거부, 연결 실패, 오프라인, 처리 실패 상태

이 순서는 디자인과 구현 순서이며, 실제 구현·실행 검증 전에는 관련 `Tasks` 항목을 완료 처리하지 않는다.
