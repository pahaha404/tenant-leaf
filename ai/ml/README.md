# AI 학습과 평가

`ai/ml/`은 건물 하자 관찰 후보 모델의 학습, 평가, 라벨 규칙, 데이터셋 메타데이터를 관리합니다. 앱에서 실제 추론을 실행하는 코드는 `server/ai-worker/`에 둡니다.

## 이 저장소에 넣는 것

- 학습·평가 코드
- 재현 가능한 학습 설정 파일
- 라벨 정의와 데이터셋 메타데이터
- 익명화된 소형 예시 데이터 (팀 합의와 검토 후)
- 평가 결과 요약과 모델 카드

## 이 저장소에 넣지 않는 것

- 현장 원본 사진, 영상, 음성
- 주소, GPS, 계약서, 사람 얼굴, 차량 번호 등 개인식별 가능 정보
- 대용량 데이터셋과 학습 중간 산출물
- 모델 가중치 파일 (`.pt`, `.onnx`, `.tflite` 등)

원본 데이터와 모델 가중치는 권한을 분리한 객체 저장소 또는 학습 플랫폼에 보관합니다. 이 저장소에는 데이터셋 버전과 외부 저장 위치의 식별자만 기록합니다.

## 추천 학습 흐름

1. 수집 근거·사용 범위·보유 기간을 확인한다.
2. 얼굴·문서·주소·차량 번호·음성 등 식별 요소를 제거하거나 가명 처리한다.
3. 라벨러가 `확인 필요` 관찰 기준으로 라벨링한다. AI가 법적·안전상 하자를 확정하는 라벨은 만들지 않는다.
4. 같은 주택 또는 같은 방문 세션의 사진이 학습·검증·평가 데이터에 나뉘지 않게 장소 단위로 분할한다.
5. 모델 버전, 데이터셋 버전, 라벨 기준, 평가 결과를 함께 기록한다.
6. `server/ai-worker`는 모델의 관찰 후보와 근거 미디어 ID를 API에 전달한다.

## MVP 권장 범위

처음에는 균열, 누수 의심 흔적, 곰팡이 의심 흔적처럼 사진에서 보이는 관찰 후보만 다룹니다. "하자 있음" 확정, 수리비, 계약 판단은 모델의 범위가 아닙니다.
