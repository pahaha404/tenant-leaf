# 세입세잎 UI 페이지 · 버튼 구조 (MVP)

## 1. 목적

세입세잎은 사용자가 방을 보면서 휴대폰을 계속 보지 않아도, 스마트 글라스와 음성 안내를 따라 점검하고 사진·확인 결과를 매물별로 정리하는 임장 보조 앱이다.

이 문서는 화면 구현과 pen.dev 디자인의 기준이다. AI는 하자를 확정하지 않고 관찰 내용과 증거를 제안하며, 사용자가 최종 확인 상태를 선택한다.

## 2. MVP 핵심 사용자 흐름

```text
앱 시작
├─ 첫 사용자
│  ├─ 온보딩
│  ├─ 촬영·녹음·개인정보 안내 동의
│  ├─ 튜토리얼 선택 또는 건너뛰기
│  └─ 로그인 / 테스트 계정 시작
└─ 기존 사용자
   └─ 홈
      ├─ 새 매물 등록
      │  └─ 매물 상세 → 점검 준비
      ├─ 기존 매물 선택
      │  └─ 매물 상세 → 점검 준비
      ├─ 최근 임장 이어가기
      │  └─ 실시간 점검
      ├─ 리포트 보기
      │  └─ 매물 리포트 → 매물 비교
      └─ 내 정보 / 설정

점검 준비
├─ 스마트 글라스 연결 및 배터리 확인
├─ 카메라·마이크·위치 권한 확인
├─ 촬영 사실 안내 확인
└─ 점검 시작
   └─ 실시간 점검
      ├─ 현재 구역 안내
      ├─ 체크리스트 확인
      ├─ 중요 사진 촬영
      ├─ 사용자 확인 상태 선택
      ├─ 녹음 / STT 확인
      └─ 점검 종료
         └─ 처리 현황
            └─ 증거 사진 검토
               └─ 리포트
                  ├─ 수정
                  ├─ 매물 상세로 돌아가기
                  └─ 다른 매물과 비교
```

## 3. 페이지 목록과 주요 버튼

| --- | --- | --- | --- | --- |
| P0 | 01 온보딩 | 서비스 가치와 사용 방식을 소개한다. | 시작하기, 튜토리얼 건너뛰기 | 동의 안내 또는 튜토리얼 |
| P0 | 02 동의·권한 안내 | 촬영·녹음·위치 사용과 촬영 사실 안내를 확인한다. | 동의하고 계속, 설정으로 이동, 나중에 | 튜토리얼 / 로그인 |
| P0 | 03 튜토리얼 선택 | 영상·직접 연습·체크리스트 요약 중 학습 방식을 고른다. | 60초 영상, 직접 연습, 건너뛰기 | 로그인 / 홈 |
| P0 | 04 로그인 | 테스트 계정 또는 이메일 로그인으로 시작한다. | 테스트 계정으로 시작, 로그인 | 홈 |

| P0 | 09 점검 준비 | 기기·권한·오디오·촬영 상태를 확인한다. | 안경 연결, 다시 시도, 휴대폰으로 계속, 점검 시작 | 실시간 점검 |

| P0 | 16 임장 리포트 | 사진 근거, 사용자 확인, 미확인 항목을 매물별로 정리한다. | 내용 수정, 근거 보기, 비교하기, 매물로 이동 | 비교 / 매물 상세 |

## 4. 실시간 점검 화면의 가지형 버튼 구조

```text
실시간 점검
├─ 상단 상태
│  ├─ 안경 연결 상태 → 기기 상태 상세
│  ├─ 배터리 → 기기 상태 상세
│  └─ 점검 종료 → 종료 확인
├─ 현재 구역 카드
│  ├─ 다시 듣기 → 음성 안내 재생
│  └─ 구역 직접 선택 → 구역 선택
├─ 진행률
│  └─ 체크리스트 열기 → 체크리스트
├─ 핵심 행동
│  └─ 중요 사진 촬영 → 사진 촬영 / 증거 사진 검토
├─ 보조 행동
│  ├─ 녹음 → 녹음·STT
│  ├─ 일시정지 → 점검 일시정지 상태
│  └─ 현재 구역 선택 → 구역 선택
└─ 종료 확인
   ├─ 계속 확인하기 → 실시간 점검
   └─ 그대로 종료 → 처리 현황
```

## 5. 하단 내비게이션

| 탭 | 연결 화면 | 탭을 눌렀을 때 |
| --- | --- | --- |
| 홈 | 홈 | 진행 중인 점검이 있으면 `점검으로 돌아가기`를 우선 표시한다. |
| 점검 | 매물 목록·지도 또는 실시간 점검 | 진행 중인 점검이 있으면 실시간 점검으로, 없으면 매물 선택으로 이동한다. |
| 리포트 | 최근 리포트 목록 | 최근 리포트와 처리 중인 리포트를 표시한다. |
| 내 정보 | 내 정보 | 계정·기기·설정 진입을 제공한다. |

## 6. 공통 상태와 규칙

| 상태 | 사용자에게 보일 내용 | 가능한 행동 |
| --- | --- | --- |
| 기기 연결 실패 | 연결 실패 원인과 현재 데이터가 보존됨을 안내한다. | 다시 연결, 휴대폰으로 계속 |
| 권한 거부 | 필요한 권한과 이유를 설명한다. | 설정으로 이동, 나중에 |
| AI 관찰 있음 | AI의 중립적 관찰과 근거 사진을 보여 준다. | 사진 보기, 문제 있음 / 없음 / 확인 못함 선택 |
| 사진 업로드 실패 | 실패한 사진 목록과 재시도 가능 여부를 표시한다. | 다시 시도, 제외하고 계속 |
| 리포트 처리 중 | 사진·AI·STT·리포트별 진행 상태를 보여 준다. | 백그라운드로 이동, 다시 시도 |
| 점검 종료 확인 | 아직 확인하지 않은 항목을 요약한다. | 계속 확인하기, 그대로 종료 |

## 7. 디자인 작업 순서

1. `01 온보딩`, `05 홈`, `07 매물 등록`을 현재 디자인 톤으로 확정한다.
2. `09 점검 준비`, `10 실시간 점검`, `12 체크리스트`를 이어서 디자인한다.
3. `13 증거 사진 검토`, `15 처리 현황`, `16 임장 리포트`, `17 매물 비교`를 디자인한다.
4. `18 내 정보`, `19 설정·개인정보`와 오류·빈 화면을 디자인한다.
5. 각 화면을 Android Jetpack Compose로 하나씩 구현하고 실제 기기 또는 에뮬레이터에서 확인한다.

## 8. pen.dev에 옮길 때의 요청 단위

한 번에 전체 앱을 생성하지 않는다. 화면 1~2개씩, 기존 디자인 시스템을 유지하는 요청으로 추가한다.

예시:

```text
현재 세입세잎 디자인 시스템과 01 온보딩, 02 홈, 03 매물 등록의 색상·폰트·카드·버튼 규칙을 유지해줘.
04 점검 준비와 05 실시간 점검 화면을 오른쪽에 추가해줘.
기기 연결 실패, 배터리, 권한 확인, 현재 구역, 체크 진행률, 중요 사진 촬영, 다시 듣기, 일시정지, 종료 상태를 포함해줘.
기존 프레임은 삭제하거나 수정하지 마.
```
