# 세입세잎 서버 작업 규칙

이 문서는 루트 `AGENTS.md`의 공통 규칙을 보완한다. 루트 규칙은 계속 적용하며, `server/` 안의 작업에는 아래 세부 규칙을 추가로 적용한다.

## 기술 환경

- API 서버는 JDK 21 LTS, Kotlin, Spring Boot 4.1을 사용한다.
- 빌드와 테스트는 저장소에 포함된 Gradle Wrapper로 실행한다.
- 데이터베이스는 PostgreSQL 17, Spring Data JPA와 Flyway를 사용한다.
- 요청·응답 코드 생성에는 OpenAPI Generator, 테스트에는 JUnit 5를 사용한다.
- 임의로 기술 버전을 변경하거나 다른 프레임워크를 추가하기 전에 영향 범위와 팀 합의를 확인한다.

## 폴더 책임

- `server/api/`는 인증, 매물, 임장, 체크리스트, 프레임 업로드와 AI 결과 조회를 담당한다.
- `server/ai-worker/`는 사진 분석, STT와 오래 걸리는 비동기 작업을 담당한다.
- API의 HTTP 요청 처리 과정에서 무거운 AI 추론을 직접 실행하지 않는다. API는 작업을 요청하고 처리 상태와 결과를 관리한다.

## API 계약

- 공통 OpenAPI 명세를 API 요청·응답 타입의 기준으로 사용한다.
- `build/generated/` 아래 자동 생성 코드는 직접 수정하거나 Git에 커밋하지 않는다. 변경이 필요하면 원본 OpenAPI 명세를 수정하고 다시 생성한다.
- 요청·응답 필드나 상태값을 변경하면 OpenAPI 명세, 계약 문서, 서버 구현과 계약 테스트를 같은 변경에서 수정한다.
- 아직 합의되지 않은 API, 필드, 오류 코드와 enum 값은 임의로 추가하지 않는다.
- JPA Entity를 API 요청·응답으로 직접 노출하지 않고 생성된 OpenAPI 모델로 변환한다.

## Kotlin과 Spring 구현

- Controller는 HTTP 요청 수신, 검증 결과 전달과 응답 변환만 담당한다.
- 비즈니스 규칙과 트랜잭션 경계는 Service에 둔다.
- 데이터 조회와 저장은 Repository에 둔다.
- 생성자 주입을 사용하고 필드 주입을 사용하지 않는다.
- Kotlin 타입으로 null 가능성을 명확히 표현하고 `!!` 사용을 피한다.
- 도메인 규칙을 Controller, Entity 콜백 또는 임의의 유틸리티에 분산하지 않는다.

## 데이터베이스

- DB 구조 변경은 새 Flyway 마이그레이션 파일로 적용한다.
- 이미 적용됐거나 공유된 마이그레이션 파일은 수정하거나 삭제하지 않는다.
- 금액은 원(KRW) 단위 정수로 저장한다.
- 면적은 제곱미터를 기준값으로 저장하며 평 값을 중복 저장하지 않는다.
- 사진 원본은 PostgreSQL에 저장하지 않고 접근 제어된 객체 저장소에 보관한다. DB에는 식별자와 필요한 메타데이터만 저장한다.

## 보안과 개인정보

- API 키, 비밀번호, 토큰, 실제 주소, 계정 정보와 촬영 자료를 Git에 커밋하지 않는다.
- 비밀번호, 토큰, DB 연결 문자열, 서명 URL과 개인정보를 로그에 출력하지 않는다.
- 매물, 임장, 체크리스트와 촬영 자료를 조회하거나 변경할 때 요청 사용자의 소유권과 권한을 검증한다.
- 부동산 연락처는 사용자가 직접 작성한 참고 정보이며 서버가 정확성을 보증하지 않는다.
- 내부 저장소 경로나 영구 접근 가능한 미디어 URL을 앱에 노출하지 않는다.

## AI 결과 처리

- AI 결과를 하자, 위험 또는 안전 상태의 확정 판정으로 표현하지 않는다.
- `Detection`은 근거 프레임이 연결된 `확인 필요 관찰 후보`로 처리한다.
- 체크리스트 최종 상태는 사용자가 확인한 경우에만 변경한다.
- 결과에는 모델 버전, 근거 `frameId`, `confidence`와 사용자 검토 상태를 기록한다.
- AI 작업자의 결과를 저장하기 전에 분석 ID, 프레임 ID, 라벨, 신뢰도와 좌표 범위를 검증한다.

## 오류 처리

- API 오류는 공통 `ErrorResponse` 형식을 사용한다.
- 사용자에게 보여 줄 `message`와 클라이언트가 분기할 안정적인 `code`를 구분한다.
- 내부 예외 메시지, SQL, 저장소 경로와 스택 트레이스를 API 응답으로 노출하지 않는다.
- 예상 가능한 도메인 오류는 명시적인 오류 코드와 적절한 HTTP 상태로 변환한다.

## 검증과 완료 조건

- 변경 후 OpenAPI 문법 검사, Kotlin 코드 생성, 컴파일과 관련 테스트를 실행한다.
- 기본 전체 검증은 `server/api/`에서 다음 명령으로 실행한다.

```powershell
.\gradlew.bat clean test
```

- PostgreSQL 연동 테스트 전 Docker 컨테이너가 `healthy`인지 확인한다.
- 테스트가 실패하면 실패 원인과 미검증 범위를 기록한다. 구현과 필요한 검증이 모두 끝난 작업만 완료 처리한다.

## Git 작업

- `main`과 `develop`에 직접 푸시하지 않는다.
- API 기능은 `feature/api-*` 브랜치에서 작업하고 `develop` 대상 Pull Request를 만든다.
- 커밋 전에 `git status`와 diff를 확인하고 해당 작업과 관련된 파일만 스테이징한다.
- 다른 담당자의 변경, 생성 목적을 모르는 파일과 사용자 파일을 임의로 삭제하거나 되돌리지 않는다.
