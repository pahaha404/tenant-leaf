# Android 앱 개발 요청

> 상태: 최신 결정 반영본
> 기준일: 2026-08-18
> 현재 작업 브랜치: `feature/android-property-crud`

## 1. 역할

15년차 Android 앱 개발자이자 AI 글래스 연동 경험이 있는 개발자의 관점으로 구현한다.

## 2. 기준 문서와 우선순위

아래 문서를 구현 기준으로 사용한다.

1. `server/backendmds/도메인 규칙.md`
2. `server/technical/api-spec.md`
3. `server/shared-types/openapi/openapi.yaml`
4. `design/UI/UI.pen`

`UI.pen`은 화면의 시각적 기준이지만 아직 작업 중이다. UI와 최신 도메인·API 계약이 충돌하면 도메인과 API 계약을 우선한다. 미확정 필드나 상태값은 Android 코드에서 임의로 만들지 않는다.

## 3. 현재 상황

- Kotlin·Spring Boot 서버와 PostgreSQL 로컬 실행 환경이 준비되어 있다.
- 매물 등록·목록/상세 조회·수정·삭제 API가 구현되어 있다.
- Android 폴더에는 안내용 뼈대만 있으므로 실행 가능한 앱 모듈과 공통 구조가 필요하다.
- 프론트엔드 담당자가 별도로 UI를 작업하고 있으므로 이번 작업은 기능·상태·데이터 흐름을 중심으로 구성한다.
- 디자인을 나중에 교체할 수 있도록 화면과 비즈니스 로직, 네트워크 코드를 분리한다.
- OpenAPI 1.2에는 이전 체크리스트 계약이 남아 있으므로 매물 CRUD 이외의 임장·미디어·분석 타입은 `09. 공통 API 및 OpenAPI 보완 요청.md`가 완료된 뒤 연결한다.

## 4. 이번 작업 범위

이번 작업에서는 아래 두 단계까지만 구현한다.

### 4.1 Android 기본 프로젝트

- Gradle Wrapper와 실행 가능한 `:app` 모듈을 구성한다.
- Kotlin과 Jetpack Compose 기반의 최소 앱을 실행한다.
- 화면, ViewModel, 비즈니스 로직과 데이터 접근을 분리한다.
- ViewModel은 `StateFlow`로 로딩·성공·빈 결과·오류 상태를 노출한다.
- 네트워크 계층과 API 모델 변환 계층을 공통 영역에 둔다.
- UI 코드에서 Retrofit·HTTP 클라이언트나 서버 DTO를 직접 다루지 않는다.
- Meta SDK 의존 코드는 `glasses/android-integration/` 경계 밖으로 퍼뜨리지 않는다.

### 4.2 매물 CRUD 연결

- 로컬 에뮬레이터의 API 기본 주소는 `http://10.0.2.2:8080/api/v1`을 사용한다.
- 사용자가 등록한 매물 목록과 상세 정보를 조회한다.
- 매물을 등록·수정·삭제한다.
- 서버의 확정 OpenAPI 필드만 사용한다.
  - 이름
  - 주소 요약
  - 보증금
  - 월세
  - 관리비
  - 전용면적(㎡)
  - 층수
  - 옵션
  - 부동산 연락처
- 서버에는 면적을 ㎡로 보내며 앱에서만 평으로 변환해 입력·표시한다.
- `1평 = 3.305785㎡`를 사용하고 평 값을 별도로 저장하지 않는다.
- 부동산 연락처는 사용자가 작성한 참고 정보이며 앱이 정확성을 보증하지 않는다.
- 로딩, 빈 목록, 입력 검증 실패, 네트워크 실패와 서버 오류를 각각 표시한다.
- 아직 실제 로그인 API를 사용하지 않고 확정된 데모 사용자 흐름을 따른다.

## 5. 확정된 촬영·분석 흐름

다음 흐름은 후속 Android·안경·미디어 기능을 구현할 때 반드시 지킨다.

```text
AI 글래스 기본 고화질 영상 촬영
→ Meta AI 동반 앱을 통해 휴대전화 갤러리로 가져오기
→ Android에서 분석용 JPEG 생성
→ 촬영 종료 후 JPEG만 API·파일 저장소에 업로드
→ AI Worker 비동기 분석
→ 구역별 확인 필요 관찰과 근거 사진 조회
```

### 5.1 사용하지 않는 방식

- 카메라 스트림을 서버로 보내지 않는다.
- 촬영 중 실시간 AI 분석을 실행하지 않는다.
- 원본 영상을 API, PostgreSQL, 객체 저장소 또는 AI Worker에 업로드하지 않는다.
- 휴대전화의 갤러리 URI와 로컬 파일 경로를 서버에 보내거나 로그에 남기지 않는다.
- Android 앱이 AI 제공자 API를 직접 호출하거나 API 키를 보관하지 않는다.

### 5.2 원본 영상과 JPEG 생성

- 원본 영상은 사용자의 휴대전화 갤러리에만 저장하고 보관·삭제는 사용자가 관리한다.
- 영상 클립마다 Android가 로컬 `sourceVideoId`를 생성한다.
- 기본 영상 녹화를 중단하거나 화질을 낮추지 않고 촬영 중 JPG를 만들 수 있는지 공식 SDK와 실기기에서 검증한다.
- 검증에 성공하면 촬영 중 생성한 JPG를 사용한다.
- 지원되지 않거나 불안정하면 촬영 완료 영상에서 2~3초 구간마다 JPEG 후보를 추출한다.
- 가능하면 각 구간에서 흔들림·어두움·가림·중복이 적은 한 장을 선택한다.
- JPEG 품질 기본값은 90이며 서버 제한인 사진당 1MiB를 넘으면 픽셀 크기보다 JPEG 품질을 먼저 조정한다.
- 실제 너비, 높이, 파일 크기와 촬영 시각을 기록한다.

### 5.3 서버에 전송하는 프레임 정보

- `frameOrigin`
  - `during_recording_capture`
  - `post_recording_extraction`
- `sourceVideoId`
- `sourceVideoOffsetMs`
- `capturedAt`
- `contentType: image/jpeg`
- 실제 `width`, `height`, `contentLength`

촬영을 종료한 임장에만 JPEG 업로드와 분석 요청을 수행한다. 개별 사진 업로드가 실패하면 성공한 사진을 다시 올리지 않고 실패한 사진만 재시도할 수 있게 한다.

## 6. 체크리스트 대신 사용하는 화면과 데이터

현장 점검에서는 체크리스트 항목별 상태, 완료율과 AI 결과의 체크리스트 매칭을 사용하지 않는다.

### 6.1 구역

- 현관·공용
- 주방
- 창틀·환기
- 거실·방
- 화장실
- 구역 확인 필요

### 6.2 분석 진행 화면

- 휴대전화 영상 가져오기 상태
- JPEG 생성 진행률
- 업로드 대기·진행·실패 수
- 구역별 분석 상태
- 실패 사진 재시도
- 완료된 구역 결과 우선 조회

### 6.3 관찰 결과 화면

- `확인 필요 관찰` 또는 `하자 의심 흔적`으로 표현한다.
- 관찰 유형, 설명, 모델 신뢰도와 모델 버전을 표시한다.
- 각 관찰에는 서버에 업로드된 근거 사진을 연결한다.
- AI 결과를 실제 하자, 안전 상태, 수리 필요 또는 계약 가능 여부의 확정 판단으로 표현하지 않는다.
- 관찰이 없다는 이유로 `문제 없음` 또는 `안전함`으로 표시하지 않는다.
- 사용자는 관찰을 열람하고 리포트에서 제외할 수 있다.

## 7. 후순위 기능

아래 기능은 서버 API와 계약이 확정된 뒤 별도 브랜치에서 구현한다. 현재 앱 구조에 빈 API 호출이나 임의의 DTO를 미리 만들지 않는다.

- 실제 회원가입·소셜 로그인·액세스/리프레시 토큰
- 약관·개인정보 동의 이력
- 온보딩·안심 가이드 완료 상태 동기화
- 푸시 알림 토큰과 알림 설정
- 오늘의 점검 팁과 자취 매거진
- 음성 녹음과 STT
- 리포트 생성·공유
- 여러 매물 비교
- 개인 맞춤 추천
- 사용자 선호 조건과 북마크

방문 전 안심 가이드는 학습 콘텐츠로만 유지하며 임장 체크리스트, 분석 결과 또는 리포트와 연결하지 않는다.

## 8. 후속 구현 순서

1. Android 기본 프로젝트 빌드
2. 매물 CRUD API 연동
3. 에뮬레이터에서 등록·조회·수정·삭제 확인
4. 임장 세션 계약 보완과 서버 API 구현
5. 방문 준비·촬영 상태 화면
6. 실기기에서 기본 영상 촬영·갤러리 가져오기·촬영 중 JPG 생성 가능 여부 검증
7. 촬영 후 JPEG 추출과 품질 선별
8. JPEG 업로드·분석 상태·재시도
9. 구역·관찰·근거 사진 화면
10. 리포트와 나머지 후순위 기능

## 9. 완료 기준

- `android/`에서 Gradle Wrapper로 Debug 앱 빌드와 단위 테스트가 통과한다.
- 에뮬레이터에서 앱이 실행된다.
- 로컬 Spring Boot 서버에 연결해 매물 등록·목록/상세 조회·수정·삭제가 동작한다.
- ㎡·평 변환과 입력값 검증 테스트가 통과한다.
- 화면 코드와 네트워크·도메인 로직이 분리되어 이후 `UI.pen` 디자인을 교체할 수 있다.
- 실시간 분석, 원본 영상 업로드와 체크리스트 중심 현장 점검 코드를 만들지 않는다.
- 서버에 아직 없는 기능은 구현 완료로 표시하지 않는다.
- 변경 파일과 실행·테스트 결과를 작업 문서에 기록한다.

## 10. 실기기 검증 전 미확정 항목

- Android 앱이 Meta 안경의 기본 녹화 시작·종료를 직접 제어할 수 있는 범위
- Meta AI 동반 앱의 갤러리 가져오기 완료를 Android 앱이 확인할 수 있는 방법
- 기본 영상 녹화 중 JPG 동시 생성 지원 여부와 영상 화질 영향
- 녹화 시작 시각과 `sourceVideoOffsetMs`를 정확히 맞추는 방법
- 지원 안경의 영상 코덱·해상도·클립 최대 길이

위 항목은 실제 SDK와 안경에서 확인하기 전까지 지원된다고 가정하지 않는다. 동시 JPG 생성이 불가능해도 촬영 완료 영상에서 2~3초 간격으로 JPEG를 추출하는 대체 흐름이 항상 남아 있어야 한다.
