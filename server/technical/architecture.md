# 개발 아키텍처

## 배포 단위

| 단위 | 경로 | 배포 방식 | 책임 |
| --- | --- | --- | --- |
| Android 앱 | `android` | Android APK/AAB | 화면, 사용자 입력, 권한, 현장 점검 상태 |
| 안경 연동 | `glasses/android-integration` | Android 앱에 포함 | Meta SDK 연동, 기본 영상 촬영·가져오기 사용자 흐름, 조건부 사진 캡처 검증, 터치, 배터리 |
| API 서버 | `server/api` | 컨테이너 | 인증, 매물/세션/체크리스트 저장, 업로드, 결과 제공 |
| AI 작업자 | `server/ai-worker` | 별도 컨테이너 | 비동기 사진 분석, STT, 보고서 초안 생성 |

`glasses/adapter`는 앱의 다른 코드가 Meta SDK에 직접 의존하지 않게 하는 인터페이스 계층입니다. 실제 SDK 구현은 `glasses/android-integration`이 담당합니다.

## 요청 흐름

1. Android 앱이 임장을 시작하고 API 서버에서 `Inspection`을 생성한다.
2. 사용자가 Meta 안경의 기본 고화질 녹화 기능으로 임장 영상을 촬영한다.
3. 사용자가 Meta AI 동반 앱의 가져오기 흐름을 거쳐 원본 영상을 휴대전화 갤러리에 보관한다. 원본 영상은 서버에 올리지 않는다.
4. Android 앱은 촬영 중 정지 사진 동시 생성이 실기기에서 지원되면 그 사진을 사용하고, 지원되지 않으면 촬영 완료 영상에서 2~3초 간격으로 JPEG를 추출한다.
5. 앱은 촬영 종료 후 API 서버에서 발급한 업로드 주소로 JPEG만 올린다.
6. API 서버는 AI 작업자에 비동기 분석 작업을 요청한다.
7. AI 작업자는 관찰 후보, 근거 사진, 신뢰도와 처리 상태를 저장한다.
8. 앱은 촬영 후 분석 진행 상태와 구역별 관찰 결과를 보여준다.

## 경계 규칙

- 안경은 서버에 직접 접속하지 않는다.
- 앱은 AI 제공자 API 키를 보관하지 않는다.
- MVP에서는 카메라 스트림을 서버에 전송하거나 촬영 중 AI 분석을 실행하지 않는다.
- 기본 녹화의 앱 제어, 가져오기 완료 감지와 촬영 중 사진 생성은 공식 SDK·실기기 확인 전까지 보장 기능으로 간주하지 않는다.
- 휴대전화의 원본 영상 경로와 갤러리 URI는 서버에 전송하지 않는다.
- API 서버의 HTTP 요청 안에서 무거운 AI 분석을 끝내지 않는다.
- AI 결과는 `Detection`이며 하자 후보인 `확인 필요 관찰 결과`다. `ChecklistItem`의 최종 상태는 사용자가 확정한다.
- 계약 변경은 `server/shared-types`와 `server/technical/api-spec.md`를 같은 변경 묶음에서 갱신한다.
