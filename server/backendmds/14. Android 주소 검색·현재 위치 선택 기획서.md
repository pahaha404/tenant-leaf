# Android 주소 검색·현재 위치 선택 기획서

> 상태: 제품 흐름 승인 반영, API 계약은 팀 검토 전, 구현 전
> 기준일: 2026-08-20
> 대상 화면: `점검할 방을 알려주세요`가 표시되는 매물 등록 화면
> 대상 경로: `android/`, `server/api/`, `server/shared-types/`, `team/00_shared/`
> 영속화 결정: 서버에는 기존 `addressSummary`만 저장하고 좌표는 저장하지 않는다.

## 1. 목적

매물 등록 화면의 주소 입력을 다음 세 경로로 완료할 수 있게 한다.

1. 도로명 또는 건물명 검색
2. 지도에서 위치 선택
3. 휴대전화의 현재 위치에서 시작해 핀 조정

어떤 경로를 사용하더라도 앱이 주소를 자동 확정하지 않는다. 사용자가 주소와, 지도를 사용했다면 핀 위치를 확인하고 `이 주소 사용`을 눌러야 매물 등록 폼에 반영한다.

현재 위치는 휴대전화의 위치이며 점검 대상 방의 위치라는 보장이 없다. Meta 안경은 이 기능에 관여하지 않고 서버와 직접 통신하지 않는다.

## 2. 현재 상태와 기준

- `android/app/src/main/kotlin/feature/property/PropertyScreens.kt`의 주소 입력은 일반 `OutlinedTextField`다.
- 입력값은 화면의 `remember` 상태에만 있고 자동완성, 지도, 위치 조회가 없다.
- `android/app/src/main/kotlin/navigation/AppNavGraph.kt`의 등록 동작은 현재 목록 화면으로 이동할 뿐 실제 매물 저장을 호출하지 않는다.
- `android/app/src/main/AndroidManifest.xml`에는 `INTERNET`과 위치 권한이 없다.
- `android/settings.gradle.kts`와 `android/app/build.gradle.kts`에는 Kakao 저장소·지도·위치 SDK가 없다.
- Android에는 서버 API transport, 인증 전달과 OpenAPI 타입 생성 파이프라인이 없다.
- `server/shared-types/openapi/openapi.yaml`의 매물 계약은 `addressSummary` 문자열만 제공하며 위도·경도 필드는 없다.
- `server/backendmds/도메인 규칙.md`는 비교에 필요한 최소 주소 요약만 저장하도록 정한다.

따라서 이번 기획은 주소를 찾고 확인하는 입력 흐름을 추가하되, 매물 데이터 계약과 DB에는 좌표를 추가하지 않는다.

현재 Android 화면은 주소를 필수로 검사하지만 매물 API의 `addressSummary`는 선택값이다. 이번 기능은 화면 규칙을 유지하고 서버 필수 여부는 바꾸지 않는다. 또한 현재 등록 버튼은 매물 API를 호출하지 않으므로, 이번 기능의 Android 완료 경계는 확정한 `addressSummary`를 폼으로 돌려주는 데까지다. 실제 매물 생성 연동은 기존 매물 API 연결 작업에서 검증한다.

## 3. 검토한 접근과 결정

| 접근 | 장점 | 단점 | 결정 |
| --- | --- | --- | --- |
| Kakao Local + Kakao Maps 단일 제공자 | 한국 도로명·건물명 검색, WGS84 좌표, 역지오코딩과 Android 지도를 한 체계로 연결 | 앱 키 설정, 쿼터·비용 확인 필요 | **MVP 채택** |
| 행정안전부 도로명주소 + Kakao Maps | 법정 도로명주소 검색에 강함 | 두 제공자, 좌표계·약관·오류 처리 증가 | 법정주소 정확성이 별도 요구될 때 검토 |
| 좌표를 매물 계약에 영구 저장 | 이후 매물 지도 화면에 바로 사용 가능 | OpenAPI·DB·서버·개인정보 정책이 모두 확대 | 이번 범위에서 제외 |

MVP는 Kakao 한 제공자만 사용한다. 제공자 교체용 공통 인터페이스나 다중 제공자 fallback은 만들지 않는다. 탐색적 주소 표본에서 특정 주소 범주가 반복해서 검색되지 않거나 법정주소 정확성이 요구될 때만 행정안전부 도로명주소 검색을 별도 변경으로 검토한다.

## 4. 범위

### 4.1 포함

- 주소 필드를 눌러 별도 주소 찾기 화면으로 이동
- 도로명·건물명 검색 결과 최대 5개 표시
- 검색 결과에서 도로명주소와 지번주소 구분
- 검색 결과 선택 후 지도와 주소 확인
- 지도 중앙 핀 이동 후 역지오코딩
- `현재 위치로 찾기`를 누른 시점의 단일 위치 조회
- 대략적 위치 허용, 권한 거부와 위치 서비스 꺼짐 처리
- 주소 직접 입력 fallback
- 사용자가 확정한 최소 주소를 기존 `addressSummary`로 전달
- 검색·역지오코딩용 서버 프록시와 의미 계약·OpenAPI 계약
- 단위·계약·Compose UI·실기기 검증 기준

### 4.2 제외

- 매물의 위도·경도 영구 저장
- 매물 목록을 지도 핀으로 표시하는 기능
- 백그라운드 위치, 연속 추적, 이동 경로, 지오펜싱
- 길찾기, 거리·소요 시간, 주변 시설 추천
- 주소 검색 기록과 최근 위치 저장
- 아파트 동·층·호 등 상세주소 서버 저장
- 오프라인 지도 또는 별도 지도 타일 캐시
- 행정안전부·NAVER·Google 동시 연동
- 제공자 추상화 계층
- 법적 주소 진위 또는 점검 대상 방 일치 보증
- Android의 전체 매물 API 연동과 매물 생성 화면의 서버 저장

좌표 저장과 매물 지도는 실제 사용자 요구가 확인된 뒤 P1로 분리한다. 그때 공통 API 계약, OpenAPI, DB migration, 서버와 Android를 같은 변경에서 수정한다.

## 5. 핵심 사용자 흐름

```text
매물 등록 주소 필드
    |
    +-- 주소 검색 ------ 검색 결과 선택 --------+
    |                                       |
    +-- 지도에서 선택 -- 지도 이동·중앙 핀 -----+--> 주소·위치 확인 --> 이 주소 사용
    |                                       |
    +-- 현재 위치 ------ 권한·설정 확인 --------+
    |
    +-- 직접 입력 -------------------------------> 직접 입력 확인 --> 이 주소 사용
```

### 5.1 진입

1. 매물 등록 화면의 주소 필드를 누른다.
2. 앱은 `주소를 찾아주세요` 화면으로 이동한다.
3. 화면 진입만으로 위치 권한을 요청하지 않는다.
4. 기존에 확정한 주소가 있으면 검색창과 확인 카드에 유지한다.

### 5.2 주소 검색

1. 검색창 문구는 `도로명 또는 건물명을 입력하세요`로 한다.
2. 검색어가 주소 검색을 위해 세입세잎 API와 Kakao에 일시 전송된다는 안내를 검색창 가까이에 제공한다.
3. 앞뒤 공백을 제거한 검색어가 2자 이상일 때 요청한다.
4. 입력 후 350ms 동안 변경이 없을 때 요청하고 이전 요청은 취소한다.
5. 서버는 Kakao 주소 검색을 먼저 호출한다.
6. 주소 결과가 없을 때만 Kakao 키워드 검색으로 건물명을 찾는다.
7. 결과는 최대 5개만 표시한다.
8. 새 요청 결과만 화면에 반영하고 늦게 도착한 이전 응답은 버린다.

검색 결과 한 항목에는 다음만 표시한다.

- 건물명 또는 결과 라벨
- 도로명주소
- 도로명주소가 없을 때 지번주소
- 도로명·지번을 함께 제공할 수 있으면 보조 문구로 지번주소

### 5.3 검색 결과 확인

1. 사용자가 결과를 누르면 해당 좌표를 중심으로 지도 확인 화면을 연다.
2. 지도 중앙에는 하나의 고정 핀만 표시한다.
3. 주소 카드에 저장될 `addressSummary`를 보여준다.
4. `이 주소 사용`을 눌러야 매물 등록 폼에 반영한다.
5. 검색 결과를 선택한 뒤 주소 문자열을 수정하면 이전 좌표 연결은 버리고 직접 입력으로 취급한다.

### 5.4 지도에서 선택

1. 지도는 기존 검색 결과 위치가 있으면 그 위치에서 시작한다.
2. 검색 결과가 없으면 대한민국 전체를 볼 수 있는 범위에서 시작한다. 서울을 임의 기본 위치로 확정하지 않는다.
3. 사용자는 지도를 움직여 중앙 핀의 위치를 바꾼다.
4. Kakao 지도 `OnCameraMoveEnd`가 전달한 최종 좌표로 이동 종료당 한 번만 역지오코딩한다. 카메라 이동 직후 좌표를 임의로 읽지 않는다.
5. 새 이동이 시작되면 진행 중인 역지오코딩 요청을 취소하고 늦은 응답을 버린다.
6. 도로명주소가 있으면 우선하고, 없으면 지번주소를 제안한다.
7. 역지오코딩에 실패해도 핀 조작과 주소 직접 입력은 유지한다.

지도 최초 로딩에 따른 카메라 콜백은 사용자 이동으로 취급하지 않는다. 검색 결과에서 진입했으면 이미 받은 주소를 유지하고, 현재 위치나 사용자의 지도 이동 뒤에만 역지오코딩한다.

`지도에서 선택`으로 직접 진입한 경우에는 첫 역지오코딩 전에 핀 좌표가 Kakao Maps SDK에서 처리되고 주소 변환을 위해 세입세잎 API와 Kakao Local REST로 전송된다는 안내를 보여 준다. 앱과 세입세잎 서버는 좌표를 저장하지 않으며 Kakao 처리는 Kakao 정책에 따른다고 구분한다.

지도만으로 기능을 완료하도록 강제하지 않는다. 화면 읽기 도구 사용자와 세밀한 지도 조작이 어려운 사용자는 검색 또는 직접 입력으로 같은 결과를 만들 수 있어야 한다.

### 5.5 현재 위치로 찾기

1. 사용자가 `현재 위치로 찾기`를 누른다.
2. 좌표가 지도 표시·주소 변환을 위해 Kakao Maps SDK, 세입세잎 API와 Kakao Local REST로 전송된다는 안내를 보여 준 뒤, 이 시점에만 전경 위치 권한을 요청한다. 앱과 세입세잎 서버는 좌표를 저장하지 않으며 Kakao 처리는 Kakao 정책에 따른다고 구분한다.
3. Android 12 이상에서는 `ACCESS_COARSE_LOCATION`과 `ACCESS_FINE_LOCATION`을 함께 요청한다.
4. 대략적 위치만 허용돼도 기능을 계속한다.
5. `Priority.PRIORITY_HIGH_ACCURACY`인 단발 `LocationRequest`로 `SettingsClient.checkLocationSettings()`를 호출하고, 해결 가능한 경우 Android 시스템 활성화 다이얼로그를 사용한다. 사용자가 활성화를 취소하면 현재 위치 흐름만 끝내고 수동 경로를 유지한다.
6. 같은 우선순위와 `Granularity.GRANULARITY_PERMISSION_LEVEL`을 설정한 `CurrentLocationRequest`로 `FusedLocationProviderClient.getCurrentLocation(..., CancellationToken)`을 한 번 호출한다. 최근 30초 이내 위치를 허용하고 최대 10초 뒤 취소하며, 화면 이탈·재시도 때도 이전 요청을 취소한다. 대략적 위치만 허용한 경우 운영체제가 낮춘 정확도를 그대로 수용한다.
7. 위치를 받으면 지도만 해당 위치로 이동한다. 주소를 자동 확정하지 않는다.
8. 결과가 `null`이면 실패로 처리한다. 대략적 위치이거나 정확도 반경이 100m보다 크면 `대략적인 위치예요. 핀을 확인해 주세요`를 표시한다. 100m는 초기 UX 기준이며 대표 기기 검증 결과로만 조정한다.
9. 사용자가 핀과 주소를 확인하고 `이 주소 사용`을 눌러야 완료한다.

### 5.6 직접 입력

- 검색 결과가 없거나 네트워크·지도·위치 기능을 사용할 수 없어도 `주소 직접 입력`을 제공한다.
- 앞뒤 공백을 제거한 한 줄 값이 1~500자이고 제어 문자가 없을 때만 사용할 수 있다. 500자는 현재 DB `address_summary VARCHAR(500)`과 맞춘다.
- 직접 입력은 외부 제공자가 검증한 주소로 표시하지 않는다.
- 상세 동·호를 요구하지 않고 비교에 필요한 최소 주소 요약만 입력하도록 안내한다.

## 6. 화면 상태와 실패 처리

| 상태 | 사용자 표시 | 계속할 수 있는 행동 |
| --- | --- | --- |
| 검색 전 | 검색 안내와 직접 입력·지도 버튼 | 검색, 지도, 직접 입력 |
| 검색 중 | 입력을 막지 않는 진행 표시 | 검색어 계속 수정, 취소 |

| 검색 실패 | `주소를 불러오지 못했어요` | 재시도, 직접 입력, 지도 |
| 요청 제한 | `요청이 많아요. 잠시 후 다시 시도해 주세요` | 안내된 시간 뒤 재시도, 직접 입력 |
| 지도 로딩 실패 | `지도를 불러오지 못했어요` | 주소 검색, 직접 입력 |
| 위치 권한 거부 | `현재 위치 없이도 주소를 찾을 수 있어요` | 검색, 수동 지도, 직접 입력 |
| 다시 묻지 않음 | 설정 이동 안내 | 설정 열기, 검색, 직접 입력 |
| 위치 서비스 꺼짐 | Android 시스템 활성화 다이얼로그 | 켜기, 취소 후 수동 진행 |
| 현재 위치 실패·시간 초과 | `현재 위치를 찾지 못했어요` | 재시도, 수동 지도, 검색 |
| 대략적 위치 | 정확도 안내 | 핀 조정, 검색, 확인 |
| 역지오코딩 실패 | `이 위치의 주소를 찾지 못했어요` | 주소 직접 입력, 지도 재조정 |

오류가 나도 검색어, 직접 입력값과 이미 확정한 주소를 지우지 않는다. 제공자 내부 오류 메시지와 키·쿼터 정보는 사용자에게 그대로 노출하지 않는다.

## 7. 권한·개인정보·보안

### 7.1 Android 권한

- 지도 네트워크 통신을 위한 `INTERNET`, 현재 위치를 위한 `ACCESS_COARSE_LOCATION`과 `ACCESS_FINE_LOCATION`을 추가한다.
- `ACCESS_BACKGROUND_LOCATION`은 추가하지 않는다.
- 화면 진입이나 주소 검색에는 위치 권한이 필요하지 않다.
- 최초 거부 후 같은 동작에서 반복 요청하지 않는다.
- 영구 거부 상태에서는 Android 앱 설정으로 이동하는 선택지를 제공한다.
- 위치 권한이 없어도 매물 등록을 완료할 수 있어야 한다.

### 7.2 일시 처리, 저장과 로그

- 검색 후보 좌표는 세입세잎 API에서 Android로 전달되고, 현재 위치·지도 핀 좌표는 지도 표시를 위해 Kakao Maps SDK에서 처리된다. 역지오코딩 때는 `Android -> 세입세잎 API -> Kakao Local REST`로 좌표가 일시 전송된다.
- 세입세잎 앱과 세입세잎 서버는 이 좌표를 요청 처리 메모리에서만 사용하고 DB, 파일, 캐시와 큐에 영속 저장하지 않는다. Kakao의 처리는 해당 서비스 약관과 개인정보 처리 조건을 따른다.
- 좌표를 `CreatePropertyRequest`, `UpdatePropertyRequest`, 로컬 검색 기록이나 분석 이벤트에 넣지 않는다.
- 프로세스가 종료되면 미확정 좌표를 복원하지 않는다.
- 확정 후 서버에 저장하는 값은 기존 `addressSummary`뿐이다.
- 실제 주소, 검색어, 위도·경도는 애플리케이션 로그, 서버 access log, analytics, crash breadcrumb와 테스트 fixture에 남기지 않는다.
- 검색과 역지오코딩 응답에 `Cache-Control: no-store`를 적용하고 별도 캐시를 만들지 않는다.

민감한 검색어가 URL·프록시 로그에 남지 않도록 앱과 세입세잎 API 사이는 `GET` 쿼리 대신 `POST` JSON 요청을 사용한다. Kakao로 보내는 외부 요청 URL도 서버 로그에서 query string을 기록하지 않는다.

출시 전 개인정보처리방침과 Google Play Data safety에는 주소 검색어와 대략적·정확한 위치가 주소 검색·변환 목적으로 서버와 Kakao에 일시 전송된다는 사실, 보유 여부와 삭제 기준을 실제 구현대로 기재한다. 저장하지 않는다는 이유만으로 수집·제3자 처리 고지를 생략하지 않는다.

### 7.3 API 키

- Kakao Maps Android SDK는 네이티브 앱 키를 사용하고 패키지명과 키 해시를 등록한다.
- 네이티브 앱 키는 앱 동작에 필요해 APK에 포함된다. 서버 비밀로 취급하지 말고 소스에는 직접 쓰지 않으며, 로컬·CI에서 주입하고 패키지명·키 해시 제한으로 오용을 막는다.
- Kakao Local REST 키는 Android에 넣지 않고 `server/api` 환경 변수로만 주입한다.
- REST 키에 호출 허용 IP를 설정하고 개발·운영 키를 분리한다.
- REST 키는 APK 등 Android 빌드 산출물에 포함하지 않는다. 두 키 모두 Git, 문서와 로그에 실제 값을 남기지 않는다.

### 7.4 공개 전 선행 Task: 공통 인증·프록시 보호

- 현재 서버는 OpenAPI의 `/auth/demo`와 Bearer 인증을 실제로 구현하지 않았고 Android에도 토큰 공급자가 없다. 이 주소 기능에 토큰을 하드코딩하지 않는다.
- 공통 인증 Task에서 데모 토큰 발급·서버 검증·Android 토큰 공급을 먼저 구현한다. 완료 전 위치 프록시는 loopback 또는 접근 제한된 개발망에서만 검증하고 외부에 배포하지 않는다.
- 공개 환경에서는 두 위치 API를 인증 후에만 호출하고, 인증 사용자와 요청 IP를 함께 기준으로 두 API 합산 분당 30회로 제한한다.
- 제한 초과는 `429 RATE_LIMITED`와 `Retry-After`를 반환한다. 앱은 자동 재시도하지 않는다.
- Kakao 인증 오류, 쿼터 소진과 반복 5xx는 민감정보 없는 원인 코드·횟수만 운영 지표로 남기고 알림을 보낸다. 검색어나 좌표를 지표 태그에 넣지 않는다.
- 일일 예산 경보와 차단 기준은 출시 환경의 실제 Kakao 쿼터·과금 설정을 확인해 공개 전에 고정한다.

이 절은 별도 공통 보안 Task의 범위다. 주소 picker의 비공개 구현 완료와 외부 공개 가능 상태를 구분해 기록한다.

## 8. 구성과 데이터 흐름

```text
도로명·건물명 검색
Android 앱 -> 세입세잎 API -> Kakao Local REST
                         <- 최소 후보 변환

지도 표시
Android 앱 -> Kakao Maps Android SDK

현재 위치
Android 앱 -> Fused Location Provider

핀 좌표를 주소로 변환
Android 앱 -> 세입세잎 API -> Kakao Local REST
            일시 좌표 전송, 영속 저장 없음

최종 저장
Android 앱 -> 매물 API 연동 작업 -> addressSummary만 저장
```

서버는 Spring Boot에 이미 포함된 `RestClient`를 재사용해 Kakao 응답을 앱에 필요한 최소 필드로 변환한다. P0에서는 `KakaoLocationClient` 한 구현만 두고 제공자 인터페이스, factory나 별도 HTTP 라이브러리를 추가하지 않는다.

## 9. 제안 API 계약

아래 두 작업은 이 기획서의 **제안**이며 아직 공통 계약으로 확정되지 않았다. 구현 전에 Android·서버 담당자가 합의하고 `team/00_shared/공통 api 계약.md`, `server/shared-types/openapi/openapi.yaml`, 서버 구현과 계약 테스트를 같은 변경에서 갱신한다. 매물 `Property`, `CreatePropertyRequest`, `UpdatePropertyRequest`에는 좌표 필드를 추가하지 않는다.

기존 DB 한도와 맞추기 위해 세 매물 스키마의 `addressSummary`에는 `maxLength: 500`을 함께 명시하되 선택값이라는 의미는 바꾸지 않는다. 서버와 앱은 초과 값을 조용히 자르지 않고 검증 오류로 처리한다.

OpenAPI의 `servers.url`이 이미 `/api/v1`을 포함하므로 path key에는 `/location/search`, `/location/reverse-geocode`만 쓴다.

| OpenAPI path | 전체 HTTP 경로 | `operationId` | 요청/응답 스키마 |
| --- | --- | --- | --- |
| `POST /location/search` | `POST /api/v1/location/search` | `searchLocations` | `LocationSearchRequest` / `LocationSearchResponse` |
| `POST /location/reverse-geocode` | `POST /api/v1/location/reverse-geocode` | `reverseGeocodeLocation` | `ReverseGeocodeRequest` / `ReverseGeocodeResponse` |

현재 생성 파이프라인은 서버용 Kotlin 타입만 만든다. Android는 이 기능에 필요한 최소 DTO와 `LocationApiClient`만 작성하되, 공통 Android API transport가 먼저 병합되면 반드시 그것을 재사용한다. Android용 OpenAPI 생성 파이프라인은 이번 기능만을 위해 새로 만들지 않는다.

### 9.1 주소 검색

```http
POST /api/v1/location/search
Content-Type: application/json
Authorization: Bearer <demo access token>
```

요청:

```json
{
  "query": "도로명 또는 건물명"
}
```

`LocationSearchRequest`의 `query`는 필수 한 줄 문자열이며 trim 후 2~100자이고 제어 문자를 허용하지 않는다. `LocationSearchResponse`는 필수 `items` 배열 하나를 가지며 빈 배열을 허용하고 최대 5개다.

`LocationCandidate`의 최소 필드는 다음과 같다.

```text
label           required string, 1~500자 건물명 또는 표시 라벨
addressSummary  required string, 1~500자 저장 후보
roadAddress     nullable string, 1~500자 도로명주소
lotAddress      nullable string, 1~500자 지번주소
latitude        required number(double), -90~90 일시 좌표
longitude       required number(double), -180~180 일시 좌표
```

규칙:

- 결과는 관련도 순 최대 5개다.
- `label`은 건물명이 있으면 건물명, 없으면 `addressSummary`다.
- `addressSummary`는 도로명주소, 지번주소 순으로 선택하고 둘 다 없으면 후보에서 제외한다.
- 제공자 문자열은 trim하고 제어 문자를 거부한다. 500자를 넘는 도로명·지번은 없는 값으로 취급하고, 유효한 주소가 남지 않으면 후보를 제외한다. 건물명이 500자를 넘으면 `addressSummary`를 `label`로 사용한다.
- provider 이름, 원본 응답과 provider ID는 외부 계약에 노출하지 않는다.

### 9.2 역지오코딩

```http
POST /api/v1/location/reverse-geocode
Content-Type: application/json
Authorization: Bearer <demo access token>
```

`ReverseGeocodeRequest`는 필수 `latitude` number(double, -90~90)와 `longitude` number(double, -180~180)를 가진다. `ReverseGeocodeResponse`는 필수 `addressSummary` 문자열 1~500자만 제공하고 요청 좌표를 반복하지 않는다.

### 9.3 오류

- 잘못된 검색어·좌표: `400`, 기존 `ErrorResponse`와 `VALIDATION_ERROR`
- 인증 없음·만료: `401`, 기존 `UNAUTHENTICATED`
- 역지오코딩 결과 없음: `404`, `LOCATION_ADDRESS_NOT_FOUND`
- 사용자 요청 제한 초과: `429`, `RATE_LIMITED`, `Retry-After` 헤더
- Kakao timeout·5xx·쿼터 초과·인증 실패: `503`, `LOCATION_PROVIDER_UNAVAILABLE`
- 앱은 자동 재시도하지 않고 사용자 재시도와 직접 입력을 제공한다. 제공자 이름·키 상태는 노출하지 않는다.
- 서버는 Kakao `401/403/429`를 자동 재시도하지 않고 운영 알림 대상으로 분류한다. timeout·일시적 5xx도 한 사용자 요청 안에서 반복 호출하지 않는다.
- 서버 `RestClient`의 Kakao connect timeout은 2초, response/read timeout은 3초로 두고 자동 재시도하지 않는다. 두 timeout은 각각 테스트하고 대표 네트워크 검증에서만 조정한다.
- 성공·오류 응답에 `Cache-Control: no-store`를 적용한다.

현재 Android에는 공통 API client가 없다. 이번 기능이 먼저 구현되면 `LocationApiClient`는 플랫폼 `HttpURLConnection`과 `JSONObject`로 두 POST만 처리해 새 네트워크 프레임워크를 추가하지 않는다. 이후 공통 transport가 생기면 중복 stack을 유지하지 않고 그 구현으로 옮긴다.

debug의 API base URL은 BuildConfig로 `http://10.0.2.2:8080/api/v1`을 사용하고 debug manifest overlay에서만 cleartext를 허용한다. release base URL은 환경에서 주입한 HTTPS만 허용하며 release manifest에는 cleartext 예외를 포함하지 않는다.

Android의 데모 로그인과 Bearer 토큰 공급도 아직 구현되지 않았다. 토큰을 코드에 고정하지 않고 인증 transport가 준비되기 전에는 서버 위치 검색을 Fake로만 개발하며 E2E 완료 처리하지 않는다.

별도 상태 클래스 계층은 만들지 않고 하나의 불변 `UiState`에서 검색 결과, 지도 준비 여부, 현재 위치 조회 여부, 확정 후보와 사용자 표시 오류를 독립 필드로 관리한다. 검색어와 확정 주소는 화면 회전에서 유지하되 미확정 좌표는 프로세스 종료 후 복원하지 않는다.

picker로 이동해도 이름·주소·보증금·월세·주거형태·방문일·시간 등 기존 폼 입력이 사라지지 않도록 현재 `remember` 상태를 `rememberSaveable`로 바꾼다. picker는 이전 back stack entry의 `SavedStateHandle`에 `addressSummary` 문자열만 일회성으로 전달하고 폼은 소비 후 해당 키를 제거한다. 좌표는 navigation state나 `SavedStateHandle`에 넣지 않는다.

Kakao `MapView`는 Compose `AndroidView` 재구성 때 다시 만들지 않고 준비 시 `start()`를 한 번 호출한다. 화면 lifecycle에 `resume()`, `pause()`, `finish()`를 연결하고 `OnCameraMoveEnd` 좌표만 ViewModel에 전달한다.

## 11. 접근성 기준

- 주소 검색, 현재 위치, 핀 확인과 직접 입력은 텍스트로 구분한다.
- 지도 상태를 색상이나 핀 모양만으로 전달하지 않는다.
- 아이콘 버튼에는 화면 읽기용 설명을 제공한다.
- 주요 터치 대상은 최소 48dp를 확보한다.
- 검색 결과의 건물명, 도로명, 지번을 읽기 순서대로 제공한다.
- 검색 결과 수, 오류와 지도 이동 후 주소 변경은 화면 읽기 도구의 live region으로 알린다.
- 로딩 중에도 뒤로 가기와 직접 입력을 사용할 수 있게 한다.
- 글자 크기를 키워도 결과 주소와 확인 버튼이 잘리거나 겹치지 않아야 한다.
- 지도 제스처를 사용할 수 없는 사용자도 검색과 직접 입력으로 완료할 수 있어야 한다.

## 12. 테스트 계획

### 12.1 Android 단위 테스트

- 1자 입력에서는 검색하지 않음
- 2자 이상 입력 후 350ms debounce
- 입력이 바뀌면 늦은 이전 응답 대신 최신 결과만 반영
- 빈 결과와 네트워크 오류에서 입력값 유지
- 직접 입력 trim 후 1~500자 검증
- 현재 위치 요청의 timeout, `null`과 화면 이탈 취소
- 현재 위치를 받아도 사용자 확인 전에는 주소가 확정되지 않음
- 폼으로 돌려주는 결과에 `addressSummary`만 있고 위도·경도가 없음

### 12.2 서버·계약 테스트

- OpenAPI 문법과 생성 타입 검증
- 검색어 길이와 좌표 범위 검증
- 주소 검색 후 건물명 fallback 규칙
- 도로명 우선순위, 500자 제한과 Kakao 응답 최소 후보 변환
- timeout·5xx와 Kakao 401·403·429를 `503`으로 변환하고 한 요청에서 재호출하지 않음
- 서버 요청 제한의 `429`, `Retry-After`와 토큰 없음·만료 시 접근 거부
- 응답과 오류에 REST 키·Kakao 원본 오류가 포함되지 않음
- 애플리케이션 로그에 검색어·좌표가 기록되지 않음
- 매물 생성·수정 계약과 DB에 좌표가 추가되지 않음

### 12.3 Compose UI 테스트

- 기존 폼 값을 채운 뒤 주소 검색·명시적 확인·복귀했을 때 `addressSummary`와 다른 폼 값이 모두 유지됨
- 현재 위치 권한 거부 또는 설정 취소 뒤 검색·직접 입력으로 완료할 수 있음
- 검색·지도 실패에서 직접 입력이 유지되고 결과·오류를 live region으로 알림

### 12.4 실기기 검증

- Android 12 이상에서 대략적·정확한 위치 각각 확인
- 권한 최초 거부와 다시 묻지 않음 확인
- 위치 서비스가 꺼진 상태 확인
- 실내·실외에서 현재 위치 정확도 안내 확인
- 지도 이동과 앱 백그라운드·복귀 시 SDK lifecycle 확인
- 네트워크 전환·오프라인·느린 응답 확인
- 접근 제어된 QA 목록의 도로명·건물명 20개 탐색 표본에서 목표 결과의 상위 5개 포함 여부와 실패 범주를 기록

첫 탐색에는 근거 없는 합격률을 두지 않는다. 반복 실패 범주가 확인되면 사용자 영향과 직접 입력 fallback을 함께 검토해 제공자 보완 여부와 다음 수치 기준을 합의한다. 실제 주소와 GPS를 테스트 코드나 Git에 넣지 않는다. 표본 원문은 접근 제어된 QA 저장소에 두고, Git의 실기기 결과에는 주소 원문 대신 범주별 성공 수, 오차 범위와 상태 코드만 기록한다.

## 13. 완료 기준

공통 인증 Task가 먼저 완료돼야 실제 주소 검색 E2E를 완료 처리할 수 있다. 그전에도 UI·지도·현재 위치·Fake API 작업은 진행할 수 있지만 관련 Task는 `[ ]`로 유지한다.

### 13.1 기능 구현 완료

- 사용자는 주소 검색, 직접 입력, 현재 위치가 포함된 지도 중 하나로 주소 입력을 완료할 수 있다.
- 화면 진입 시 위치 권한을 요청하지 않는다.
- 현재 위치는 단일 조회만 하며 백그라운드 위치 권한이 없다.
- 대략적 위치와 권한 거부에서도 매물 등록 흐름을 계속할 수 있다.
- picker 왕복과 검색·지도·역지오코딩 실패가 주소를 포함한 기존 폼 입력을 지우지 않는다.
- 모든 경로에서 사용자의 명시적 확인 전에는 주소를 확정하지 않는다.
- 주소 찾기는 폼에 `addressSummary`만 반환하고 매물 계약·DB에 좌표 필드나 migration을 추가하지 않는다.
- 실제 주소·검색어·GPS·API 키가 Git과 로그에 없다.
- OpenAPI 검증, 서버 테스트, Android 단위·UI 테스트와 Debug 빌드가 통과한다.
- 테스트 작업이 `NO-SOURCE`가 아니며 실제 테스트 파일·실행 건수와 결과 보고서를 확인한다.
- 실제 Android 기기에서 권한·위치 설정·지도 lifecycle을 확인한다.
- 실제 검증 전에는 관련 Task를 `[x]`로 바꾸지 않는다.

### 13.2 외부 공개 완료

- Bearer 인증, 사용자·IP 요청 제한과 `Retry-After`가 운영 환경에서 동작한다.
- 좌표의 일시 전송과 앱·세입세잎 서버 미보관이 개인정보처리방침·Data safety의 실제 구현 설명과 일치한다.
- Kakao 쿼터·비용 보호, 키 제한과 운영 알림을 검증한다.
- 이 기준 전에는 위치 프록시를 외부에 공개하지 않는다.

## 14. 구현 순서

1. Android·서버 담당자가 의미 계약, 두 API, 개인정보 처리와 완료 기준을 승인한다.
2. 별도 공통 인증 Task에서 데모 토큰 발급·검증과 Android 토큰 공급을 완료한다.
3. Kakao 개발자 앱, Android 패키지·키 해시와 개발·운영 키를 준비한다.
4. 공통 의미 계약, OpenAPI와 계약 테스트를 같은 변경에서 추가한다.
5. `server/api`에 입력 검증, Kakao Local 호출, 응답 축소와 오류 변환을 구현한다.
6. Android에 최소 transport, 주소 검색과 직접 입력 흐름을 구현한다.
7. Kakao 지도 lifecycle과 단일 현재 위치 조회를 연결한다.
8. 매물 폼에는 최종 `addressSummary`만 전달되는지 검증한다. 실제 매물 저장 연동은 별도 매물 API 작업에서 검증한다.
9. 자동 테스트 후 실제 Android 기기에서 권한·위치·지도 실패 시나리오를 검증한다.
10. 구현과 필요한 검증이 모두 끝난 뒤 `공용 Task.md`, `android/android/Task.md`, `server/backend/Task.md`를 갱신한다.

## 15. 출시 전 확인

- Kakao 개발자 콘솔에서 Kakao Map API 사용 설정을 켜고 무료 쿼터 적용 배지를 확인한다. 무료 대상이 아니면 비즈월렛 연결과 유료 API 사용 설정을 배포 전에 완료한다.
- 주소 검색·역지오코딩·Android 지도의 최신 쿼터와 가격을 다시 확인한다.
- 서버 요청 제한, 일일 사용량 경보와 비용 차단 기준을 운영 환경에서 검증한다.
- 개발자별 debug 키 해시, release 키 해시와 Google Play App Signing 인증서 키 해시를 각각 등록하고 서버 REST 키 허용 IP를 확인한다.
- release AAB를 Google Play 내부 테스트 트랙에 배포해 Kakao 지도 인증을 확인한다.
- release base URL이 HTTPS이고 debug cleartext manifest가 release에 병합되지 않았는지 확인한다.
- Kakao 지도 로고와 저작권 표시가 다른 UI에 가려지지 않는지 확인한다.
- Kakao 응답 저장·표시 조건과 개인정보처리방침·Google Play Data safety의 제3자 처리 고지를 검토한다.
- 주소·좌표가 access log, analytics와 crash report에 포함되지 않는지 운영 설정으로 재확인한다.
